# 오탐 경로를 추가하지 않는 심사 속도 개선 — 최종 PR 계획

상태: **6단계 코드 구현·로컬 검증 완료, 운영 미배포.** 2026-09-21, 기준 `af50608`.

[구현 결과·테스트·배포 순서](../../operations/review-pipeline-speed-runbook.md). LAYA 실험(PR159/160)은 별도 브랜치로 유지하며 이 변경은 운영 경로에 LAYA를 넣지 않는다.

## 최종 결정

**LAYA의 예측을 운영 심사 경로에 넣지 않는다.** 승인·거절뿐 아니라 카테고리, 증거 선택, 입력 요약, 수집 범위, 처리 우선순위, 재시도·생략 여부도 맡기지 않는다. 확정되지 않은 힌트가 후속 모델의 입력을 바꾸는 간접 경로까지 제외한다.

LAYA 측정치는 빠르지만 오탐이 있었다. 속도나 confidence 임계값은 오탐이 없다는 증거가 아니다. “500ms 이내 응답이면 힌트로 사용”했던 이전 제안도 철회한다. 기존 오프라인 평가 자료는 보관하되 운영 어댑터·환경 변수·주기 호출·자동 활성화 기능은 이번 PR 범위에 없다.

대신 **이미 검증·저장된 결과를 다음 작업에 즉시 알리고, 같은 동시 호출 한도 안에서 큐를 처리하며, 발행이 번역을 기다리지 않도록 한다.** 새로운 제품 판별 규칙이나 모델은 추가하지 않는다.

## 재검토 결과

| 이전 제안 | 오탐이 영향을 주는 경로 | 최종 처리 |
|---|---|---|
| 소프트웨어/문서 빠른 분류 | 잘못된 원문 선택, 특정 후보 지연·누락 | 제외 |
| 설치 안내 판별 | 다른 프로젝트의 설치법을 해당 제품 근거로 오인 | 제외 |
| 플러그인/스킬 힌트 | 카테고리 편향, 필요한 증거 수집 누락 | 제외 |
| LAYA로 우선순위 결정 | 오분류된 후보의 지연·기아 | 제외 |
| LAYA 요약을 1·2차에 전달 | 반례 삭제, 모델 판단 유도 | 제외 |

| 별 수·중복·파일 존재 판별 | 이미 코드/DB가 확인하는 사실 | 기존 구현 유지; LAYA 미사용 |

설치 문구가 보인다는 관측도 설치 가능한 제품이라는 결론으로 승격하지 않는다. `SKILL.md` 존재, 높은 별 수, README의 명령어만으로 승인하지 않는다. 이런 의미 판단은 현재의 심사 정책·원문 검증에 남긴다.

기존 1·2차 모델 자체의 오판이 0이라는 주장은 하지 않는다. 이번 변경의 보장 범위는 **새 예측으로 결정·증거·정책을 바꾸는 경로를 추가하지 않는 것**이다. 정상 처리에서 동일 원본·정책·고정 모델 응답을 재생했을 때 발행 결과가 기존 구현과 같아야 한다. 원본·수동 문구 교체 경합에서는 PR-04가 잘못된 늦은 쓰기를 추가로 차단한다. 실제 LLM은 비결정적이므로 운영 재실행의 답변까지 같다고 보장하지 않는다.

## 변경하지 않는 계약

1. `REVIEW_PROMPT_VERSION`, `REVIEW_RULES_VERSION`, 모델·fallback·confidence 임계값, 수집/등록 기준.
2. 500개 기준의 설치형 예외와 문서·설문·자료 목록 제외 정책. 별 수만으로 승인하지 않음.
3. `ReviewInput`의 원문, 순서, 정책, evidence IDs 및 해시 산출 방식. 조기 요약·원문 발췌·새 캐시를 추가하지 않음.
4. 현재 활성 1차 승인 + 필요한 독립 2차 모델별 승인 + 반대/미완료 표 차단. 관리자 명시 결정의 기존 예외도 그대로.
5. source revision, 정책/모델 버전, 만료, lease, 동일 저장소/URL 중복 잠금, 수동 분류 보호.
6. 실패를 승인·거절로 바꾸지 않음. 기존 retryAfter, 시도 한도, Sonnet fallback 유지. Opus 추가 없음.
7. 신호는 실행 요청일 뿐 승인표가 아님. 소비자가 최신 상태와 기존 대상 조건을 다시 검사.

## 성능 근거와 목표

[이전 실측](https://github.com/JRVector9/nomorevibe/blob/09710e1/docs/operations/2026-09-21-laya-fast-precheck.md)의 재심사 후 발행 109건: 수집→1차 시작 중앙값 947.9초, 1차 실행 11.4초, 1차 완료→2차 등록 25.3초, 2차 완료→발행 35.2초. 일괄 적체가 포함된 집단이므로 현재 전체 서비스의 SLA로 사용하지 않는다. 최근 24시간의 새 1차 실행 2,399건은 중앙값 10.6초이며 결과 재사용 190건은 제외했다.

- 기능 목표: 다음 실행에 정기 스케줄을 기다릴 필요가 없게 한다. 바쁜 워커의 현재 작업은 계속 기다릴 수 있다.
- 통제된 빈 워커 실험: 결과 커밋→다음 처리 시작은 기본 poll 5초 + 실제 DB/실행 비용 범위. 정기 1분/5분 대기 없음.
- 통제된 적체 실험: 고정 지연 10초/동시성 4에서 초기 8건을 두 번의 슬롯 충전으로 처리. PR-03의 시간 예산 내 종료.
- 운영 목표: 같은 원본 규모·큐 깊이·외부 모델 상황을 나누어 p50/p95와 시간당 새 처리 건수 비교. 단축률은 배포 실측 전 확정하지 않음.

## 이번 문서 작업 검증

실행한 기존 단위 테스트: 두 실행 합계 14개 파일 **132개 통과** (심사·워커 91개 + 텍스트·역할·DB 풀 41개). 명령과 범위는 PR-01에 기록했다. 아직 작성하지 않은 PR 회귀 테스트, 통합 테스트, 배포 검증을 통과했다고 간주하지 않는다.

위 132개는 계획 작성 당시 결과이며 최신 구현 검증은 운영 절차 문서를 따른다. 현재 코드 구현은 완료했으며 운영 설정·심사/발행 데이터 변경은 없다. `brainstorming`, `writing-plans`, `systematic-debugging` 스킬을 사용하지 않았다.
