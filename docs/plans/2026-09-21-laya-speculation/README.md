# LAYA 적용 계획 — 설치형 후보의 2차 심사 선행 계산

상태: PR-01 구현·CI·실제 LAYA 인증 호출 확인 완료. 새로운 표본 평가와 운영 효과 검증은 남아 있다. 운영 적용 전. 사용자 최신 요청: LAYA를 적용하되 효과가 큰 한 부문부터 진행한다.

실제 PR: [#159 — LAYA 평가 도구](https://github.com/JRVector9/nomorevibe/pull/159), 초안. 코드 커밋 `d08f25f`. PR-02/03은 계획이며 GitHub PR을 생성하지 않았다.

## 적용 대상과 목적

**500별 이상 설치형 제품 후보의 독립 2차 심사 선행 계산**만 대상으로 한다. `LAYA → 제품일 가능성이 높음`은 추가 계산을 시작할 힌트일 뿐, 승인·거절·분류 결과가 아니다. 기존 1차와 2차는 같은 원문을 별도로 읽으므로, 여유 실행 용량에서 2차를 먼저 계산하면 두 모델을 순서대로 기다리는 시간을 겹칠 가능성이 있다.

이는 아직 입증된 운영 효과가 아니다. 기존 코드의 별 수·URL·fork 체크는 이미 매우 짧고, 전체 심사 대기의 주요 원인은 큐다. 따라서 모든 후보에 LAYA를 추가하거나 심사를 대체하지 않는다. 설치형 후보에서도 예측 적중률, 여유 슬롯, 낭비 호출을 측정해 **이득이 없으면 PR-02 운영 연결을 진행하지 않는다.**

오탐을 심사에 맡기지 말라는 기존 요구는 유지한다. LAYA가 틀렸을 때 달라질 수 있는 것은 불필요한 선행 계산의 양뿐이다. 음성·오류·미설정이면 기존 경로 그대로, 양성도 기존 1차 승인과 독립 2차 승인 없이는 발행 불가. LAYA 응답·요약·confidence를 기존 모델의 원문이나 심사 입력에 넣지 않는다.

## PR 구성

PR-01은 실제 API와 통신할 수 있는 평가 도구까지 구현한다. 웹/크롤러/심사 워커가 이 모듈을 호출하도록 연결하지 않는다. 따라서 PR-01만으로 사용자 화면이나 운영 처리 속도가 바뀌었다고 보고하지 않는다. 이후 PR은 측정 결과에 따라 착수하며, 기존 [기계적 속도 개선 6개 PR](../2026-09-21-review-pipeline-speed/README.md)을 전부 함께 구현하는 범위는 아니다.

## 유지할 계약

- 기존 제품 기준, 500별 예외, 원문, prompt/policy/model, 독립 모델 요건, Sonnet fallback 유지.
- 선행 결과는 일반 secondReviews 승인표가 아니다. 1차의 실제 성공 승인 후 최신 candidate/document/settings/scan/lease를 잠그고 전체 입력·정책·출처·모델·만료를 대조해야만 사용할 수 있다.
- `sourceRevisionHash`에는 후보 judgedAt도 포함된다. 1차 결과 기록 전후의 candidate 변경을 임의로 정규화해 재사용 범위를 넓히지 않는다. 동일성이 성립하지 않으면 버리고 정상 2차를 실행한다.
- shared gateway 동시 호출 수를 늘리지 않는다. 선행 호출은 여유 슬롯만 사용하고 정상 심사에 우선권을 준다. busy queue에서 얻을 이익이 없으면 건너뛴다.
- 작은 표본의 오답 0이나 높은 확률로 정책 관문을 없애지 않는다. 모델 결정과의 일치율은 사람 정답 기준 정확도가 아니다.

새 테스트 42개(실제 로컬 HTTP 서버를 통한 CLI 포함), 전체 단위 테스트 1,108개, 타입 검사·대상 파일 린트 통과. 커밋 `9bc53de`의 GitHub CI(통합 테스트·빌드 포함)와 GitGuardian도 통과했다.

사용자가 클립보드로 제공한 키로 실제 API 호출을 확인했다. 기존 47개 중 대상 14개 모두 응답, 중앙값 22.7ms/p95 102.7ms, 선행 계산 제안 5개 모두 기존 1차 승인과 일치했다. 재사용한 작은 표본이므로 정확도나 속도 개선 근거로 해석하지 않는다. [실측 및 대기열 점검 보고서](../../operations/2026-09-21-laya-speculation-live-check.md)를 참고한다.

이전 표본을 제외한 새 100개(기존 1차 승인 81/거절 19)는 준비·입력 검증 완료. 추가 호출 직전 클립보드 내용이 바뀌어 키 재복사를 요청했다. 키를 보관하거나 코드·PR·명령행 인수에 넣지 않았다. 12:43 KST에 1차 대기 5/2차 pending 0, 두 작업 최근 성공을 확인했지만, 이 한 시점의 값은 공유 서버의 여유 용량 증명이 아니다. PR-02 조건이 아직 충족되지 않았으므로 운영 연결은 진행하지 않는다.
