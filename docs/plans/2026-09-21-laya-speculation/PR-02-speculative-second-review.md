# PR-02 — 독립 2차 심사 선행 결과의 안전한 재사용

상태: 미구현, PR-01 실측·여유 용량 확인 후 착수. 제안 브랜치 `feat/laya-speculative-second-review`.

## 실행·저장

1. 정상 1차 호출은 LAYA를 기다리지 않고 시작한다. 후보가 설치형/500별 이상이고 실제 여유 실행 슬롯이 있을 때에만 LAYA 힌트를 병행한다. timeout/negative/malformed에는 정상 경로를 유지한다.
2. 양성 힌트와 여유 슬롯이 모두 있으면 설정된 독립 2차 모델에 **기존의 완전한 ReviewInput**을 그대로 보낸다. LAYA의 요약/질문/확률은 보내지 않는다. 기존 모델 정체성 검증을 사용한다.
3. 선행 결과 전용 테이블/제약을 둔다. 저장 키는 candidate, firstAttempt, inputHash, sourceRevisionHash, policyHash, second provider/model, question version. 결과는 미확정이며 기존 secondReviews/publication 쿼리가 읽지 않는다. 실패도 정상 2차 retry/fallback 횟수에 섞지 않는다.
4. 1차 성공 승인 후 기존 2차 enqueue/소비 지점에서 원본·후보·정책·모델·근거 세대·만료·lease를 다시 검증한다. 정확한 출처 동일성이 성립할 때에만 정상 2차 기록 경로를 통해 채택한다. 1차가 candidate source를 바꾸어 동일성이 깨지면 재사용하지 않는다.
5. 1차 거절/보류/실패, 정책·모델 변경, 수동 결정, 재수집, stale/lease 상실은 폐기. 선행 실패·미완료는 정상 2차를 막거나 늦추지 않는다. 이미 정상 2차가 claim됐다면 그 실행이 이긴다. 같은 generation+voter는 결과 1개만 채택.

## 자원·수명

공유 gateway와 워커의 현재 활성 요청 상한을 늘리지 않는 슬롯 관리가 선행 조건이다. first=4와 speculative=1을 단순히 더하는 방식은 금지한다. 정상 큐가 슬롯을 필요로 하면 선행 작업은 시작하지 않거나 취소한다. LAYA/선행 오류의 backoff는 본 심사와 분리한다. 필수 자원 조정·저장 원자성 변경 범위가 예상보다 크면 PR을 더 쪼갠다.

## 필수 회귀

- LAYA 오탐/미탐/오류에도 고정 원문·모델 응답의 최종 발행 결과 동일.
- 첫/둘째 순서가 바뀌어도 동일한 두 독립 승인 필요. 반대·보류·fallback 미완료 차단.
- 원문/scan/모델/정책/수동 결정/lease 경합 모두 오래된 결과 채택 0.
- 동일 후보 동시 재전달/정상 2차와 경쟁에서 중복 채택 0.
- 정상 큐 우선, 총 활성 요청 상한, shutdown 회수, timeout 기존경로 복귀.
- 정상 2차 시작 시 아직 선행 응답이 없으면 기다리지 않음.

실제 저장 스키마/마이그레이션은 진입 조건 충족 후 현재 코드에 맞춰 검토한다. 지금 존재하지 않는 테이블이나 실행 경로가 이미 동작한다고 가정하지 않는다.
