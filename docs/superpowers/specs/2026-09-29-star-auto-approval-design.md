# 500스타 이상 자동 승인·발행

## 승인된 정책

- 관리자의 `자동 승인 최소 스타` 기본값은 500이다. 10만 스타 이상도 같은 규칙에 포함한다. 관리자에서 기준을 500 이상으로 조정할 수 있다.
- 기준을 충족한 공개 GitHub 원본은 제품 적합성 규칙, 개발 근거, 1차·2차 AI 심사를 거치지 않고 발행한다. 500스타 미만은 기존 심사 절차를 따른다.
- GitHub API가 성공적으로 반환한 숫자 ID와 정수 스타 수를 최근 24시간 원본에서 확인한다. 포크·보관 저장소, 삭제·비공개 저장소, 기존 제품/차단 제품과의 중복은 제외한다. 관리자가 직접 거부한 후보는 자동 결정으로 덮지 않는다.
- 배포 홈페이지가 없거나 쓸 수 없으면 공식 GitHub 저장소를 접근 주소로 쓴다. 소개가 없어도 저장소 이름을 사실 그대로 표시한다. 분류 실패는 기존 규칙 분류값으로 대체한다.
- 과거 `스타 상한`은 새 정책과 충돌하고 이미 500스타 이상에 적용되지 않으므로 관리자 폼과 실제 판정에서 제거한다. 저장된 과거 필드는 호환을 위해 읽되 판정에 쓰지 않는다.

## 실행 경로

1. 수집 워커가 GitHub REST `/repos/{owner}/{repo}`의 성공 응답을 원본과 수집 시각으로 저장한다. 스타 검증 함수는 ID·스타 수·공개 여부·포크·보관 여부·수집 시각을 함께 검사한다.
2. 판정 워커는 검증된 기준 충족 후보를 `approved`로 기록하고 결정 근거, 기준값, 원본 리비전을 신호에 남긴다. 중복·차단 제품은 기존 DB 검사에서 거부한다. 성공 시 발행 잡을 요청한다.
3. 1차 심사 대상 조회는 이 후보를 제외한다. 발행 후보 조회는 기존 AI 승인 또는 현재 설정과 원본으로 검증되는 스타 자동 승인을 허용한다.
4. 발행 직전 트랜잭션은 후보·원본·설정·제품 중복을 잠그고 다시 검사한다. 기준 변경, 원본 갱신, 관리자의 결정, 수집 시각 만료가 있으면 발행하지 않는다. 스타 자동 승인에서는 AI 관문만 건너뛴다.
5. 발행 준비는 스타 자동 승인에 한해 제품 목적·개발 근거·소개/분류 보류를 건너뛰고, 직접 확인한 저장소 정보로 최소 표시값을 만든다.

## 기존 후보 적용

배포 후 읽기 전용 계획으로 500스타 이상 미발행 자동 후보를 목록화한다. 관리자 결정, 중복/차단, 이미 발행된 제품을 제외한다. 적용 단계는 각 행의 후보·원본·정책 지문을 다시 대조한 뒤 `new`와 재수집 대기로 전환한다. 새 GitHub 응답이 저장된 뒤 판정하므로 오래된 스타 수로 발행하지 않는다. 적용 건수와 발행/거부/대기 결과를 별도로 기록한다.

## 검증과 롤백

- 499/500/100000 경계, 기준 변경, 오래된/잘못된 원본, 포크·보관·중복·관리자 거부, 원본 갱신과 발행 경합을 단위·통합 시험으로 확인한다.
- 운영 적용 전 계획과 영향 건수를 확인하고, 배포 후 신규 발행에서 AI 심사 기록 없이 스타 승인 근거가 남는지 읽기 전용으로 확인한다.
- 코드 롤백은 이전 발행 정책으로 되돌릴 수 있지만 이미 발행된 제품은 자동으로 삭제하지 않는다. 필요하면 관리자 검수로 개별 처리한다.
