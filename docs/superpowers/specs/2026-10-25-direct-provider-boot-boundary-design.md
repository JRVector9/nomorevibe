# Direct native provider boot boundary

Root approved this narrow V3 design after read-only investigation of request c2acef26-0b62-4a0c-bddf-789fba97a793. Existing V1 needs an original complete process identity that was never captured for the GPU; V2 supports historical owner records with launchd, not this reboot. A new provider PID started after dispatch cannot replace the original identity. Preserve V1/V2 unchanged and add a strict direct Linux native host-reboot variant.

The immutable request tuple and full local_model_direct serving contract bind the native IPv4 endpoint, backend/group/model/deployment/token bound to the actual host machine hash, Tailnet node and old/new boot journal artifacts. The original adapter is single-use, one POST, redirect:error, default Undici Agent, no proxy/retry/durable queue. Native journal evidence must prove the entire inference world is local to this host, not a remote executor behind a rebooted frontend. These are reviewed privileged raw observations: JSON flags and hashes bind bytes but cannot establish physical authority alone.

A primary DB before/after sandwich around remote CLOCK_BOOTTIME gives a conservative boot interval, using exact integer microseconds and nanoseconds. Lower is DBbefore−ceil(uptimeNs/1000)−1us, upper is DBafter−floor(uptimeNs/1000)+1us. Require a <=5s sandwich, <=5min observation freshness and consistent host btime. Dispatch and exact same-owner/request/binding local-end event, exactly1/1, must precede both conservative lower bounds. Plan/receipt boot intervals must overlap and machine/node/IP/boot identities must match. Current boot differs from old boot. Host wall clock alone grants no recovery authority.

Original owner container identity predates dispatch and is tied through actual inside-child environment/namespace/start/run records to the application owner boot. The observed owner exit and blocked replacements follow the exact draining plan. A fresh same-native-host boot observation follows owner exit; current native provider is not stopped. Authoritative DB local-end ID/hash/time and original spawned group are rechecked under control/request locks and in the DB trigger.

Keep provider_boundary_exit, exact writer fence/control CAS, indeterminate→withdrawn only, immutable binding, canonical evidence hash, one matching event and transactional operations audit. No native terminal, usage, settlement or business result is invented. Migration0130 advances130 journal rows to131 and preserves all CHECK OIDs and prior validator bodies through additive delegation. Root owns migration, draining, owner cutoff/release/restore/open and deployment. This implementation phase changes production nothing.
