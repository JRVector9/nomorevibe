# Web, pipeline and Oracle recovery implementation

Goal: restore recoverable web/backend faults automatically, independently observe every pipeline stage from Oracle, notify the administrator, and audit every page for bottlenecks.

Architecture: retain Swarm's unlimited task replacement and fenced worker supervisor. Fix reproduced cache, network/parser and lease-acquisition failures. An independent Oracle systemd watchdog polls two constrained Docker SSH gateways and one fixed Osaka native gateway. Docker gateways expose only fixed service health and can roll the existing web/readonly monitor service after rechecking a persistent failure; the native gateway can start only its failed, empty agent-scan unit. Automated recovery never alters DB, models, policy holds, replica intent, release or application configuration. Oracle's existing Kuma/Telegram remains the notification transport. Host loss/DB failure is alerted and uses existing standby/failover; infrastructure restoration requires separate verified DR readiness.
