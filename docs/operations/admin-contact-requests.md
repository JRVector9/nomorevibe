# 관리자 문의 접수와 메이커 답장 검수

배포 전에 `0117_admin_requests` 마이그레이션을 실행한다. 기존 `maker_replies`에 검수 버전과 재검수 표시를 추가하고 비공개 `admin_contact_requests`를 만든다. 운영 DB 마이그레이션·배포는 별도로 진행한다. 웹 두 앱을 모두 새 릴리스로 배포하고 옛 웹 요청이 끝났는지 확인한 뒤 새 답장 검수를 사용한다. 옛 웹은 검수 버전·재검수 표시를 모르므로 릴리스가 섞인 기간에는 새 검수를 사용하지 않는다.

## 문의 접수

`/admin/requests`는 **관리자가 contact@nomorevibe.com으로 받은 메일을 수동으로 기록**하는 접수함이다. 메일함 연동, 자동 수집, 문의자에게 이메일 발송은 하지 않는다. 메일 공급자를 정한 뒤 별도 작업으로 연결한다.

받은 사람 주소·제목·본문과 UTC 수신 시각을 기록한다. 기본 목록은 미처리·처리 중·회신 대기이고, 완료·스팸은 상태 필터에서 다시 찾는다. 답장은 기존 메일함에서 직접 보낸 뒤 상태와 처리 메모를 저장한다. 처리 메모는 마지막 내용을 교체하며, 상태 변경 이력과 처리자·시각은 작업 로그에 남는다. 다른 관리자가 저장한 오래된 폼은 충돌로 거절되므로 새로고침한 뒤 다시 확인한다.

주소·제목·본문·처리 메모는 이 접수함 테이블에만 저장하며 공개 API를 만들지 않는다. 작업 로그에는 문의 ID·상태·버전만 남기고, 오늘 할 일의 공유 캐시에는 문의 ID·상태·수신 시각만 넣는다. 다른 공개 화면이나 외부 로그에 문의 내용을 복사하지 않는다.

## 메이커 답장 검수

`/admin/maker-replies`에서 링크가 넷 이상이라 보류된 답장을 확인하고 공개 승인·거절한다. 이미 공개한 답장도 숨기거나 복원한다. 숨긴 답장은 작성자가 여러 번 고쳐도 보류되며 관리자가 공개할 때까지 유지한다. 일반 링크 보류는 작성자가 링크를 줄이면 기존 자동 검사로 공개된다.

검수 폼의 버전은 작성자 수정과 관리자 처리마다 올라간다. 수정 후 같은 본문으로 원복해도 오래된 검수 폼을 승인할 수 없다. 작성과 검수는 같은 대상 잠금을 사용한다. 내려간 제품·숨겨진 원문·해제된 메이커 권한은 공개 승인하지 않는다.

처음 공개할 때 기존 알림 경로로 글쓴이에게 답장당 한 번 알린다. 숨기면 이미 받은 사이트 알림의 답장 인용도 제거하고, 복원해도 알림을 중복 생성하지 않는다. 알림 쓰기는 답장과 같은 트랜잭션 안의 savepoint로 처리하여 실패해도 답장은 저장한다. 관리자 감사 기록이 실패하면 검수 자체를 취소한다.

두 처리함은 관리자 메뉴와 오늘 할 일에 연결된다. 모든 서버 쓰기는 기존 DR 관문, 관리자 세션, Origin 검사와 세션별·용도별 HMAC 검사를 거친다.
