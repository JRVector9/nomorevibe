# 선택한 모델의 실제 응답 진단

`/admin/flow`의 처리 LLM 변경 서랍은 1·2·3순위를 각각 한 행으로 보여 준다. 각 행의 「응답 테스트」는 아직 저장하지 않은 연결·모델·추론 설정으로 짧은 실제 호출을 한 번 보낸다. 작업 설정이나 검수 결과는 저장하지 않는다.

## 진단 범위

- API는 기존 `probeResponseModel`의 관리자 등록 시 1-token 진단 예외를 사용한다. `GET /models`만 성공한 것을 응답 성공으로 표시하지 않는다.
- OpenCode는 기존 등록 호스트와 인증 RPC를 사용한다. 호스트 catalog에 있는 정확한 모델과 추론 설정을 확인하고, 다른 모델로 대체하지 않는다.
- 장비 상태를 읽지 못하거나 신규 호출이 닫혀 있거나 공유 여유가 없으면 호출하지 않는다. 진단은 정식 검수 슬롯 밖의 관리자 진단 예외이며 처리량 수치의 검수 완료 건수로 세지 않는다.
- 같은 장비의 진단 시작은 주 DB 감사 기록으로 1분 간격을 두고, CLI 호스트는 진단 프로세스를 한 번에 하나만 실행한다. API와 CLI 모두 짧은 고정 입력만 사용하며 브라우저에서 프롬프트·주소·인증 키를 받지 않는다.
- CLI는 기존 격리 프로필을 사용해 도구를 금지한다. 출력 토큰·출력 바이트·시간 상한을 적용하고 실제 프로세스 종료와 완료 응답을 확인한 경우만 성공이다.
- 선택을 바꾸거나 서랍을 닫으면 이전 호출의 응답을 UI에서 폐기한다. 브라우저 요청 중단을 모델 서버의 실제 작업 종료로 표시하지 않는다.

## 운영 반영 순서

웹은 새 `responseProbe` RPC를 사용하므로 별도 실행 중인 M3 CLI bridge도 같은 검토 커밋으로 갱신해야 한다. 일반 Dokploy 앱 배포만으로 네이티브 bridge가 갱신됐다고 기록하지 않는다.

1. 검토 커밋과 기존 호스트 실행 설정·인증·계정을 확인한다. 새 OpenCode를 설치하거나 업데이트하지 않는다.
2. 기존 호스트 운영 절차로 CLI bridge 소스/번들을 갱신한다. `scripts/build-cli-host.mjs`가 해당 소스를 포함하는지 확인하고 기존 서비스 관리자 절차로 반영한다. 진행 중인 검수 호출이 있을 때 임의로 프로세스를 종료하지 않는다.
3. 호스트의 실제 실행 소스·버전과 기존 catalog 동작을 확인한다. 이후 웹의 응답 테스트를 한 번 요청해 결과와 관리자 감사 시작·결과 기록을 대조한다.
4. 제한/연결 오류는 실패로 남긴다. 모델 목록 응답이나 최근 검수 성공 기록을 이번 진단 성공으로 대신 표시하지 않는다.

호스트가 구버전이면 새 진단 action을 받지 못한다. 웹에는 호스트 bridge 업데이트·연결 확인 안내가 표시되며 기존 검수 실행 RPC는 그대로 유지된다. 이 문서는 배포 완료나 실제 진단 성공 영수증이 아니다.

## 검증 범위

이 PR 개발에서는 변경 범위 정적 검사만 수행한다. 실제 운영 모델에 진단 요청을 보내거나 호스트 서비스를 재시작하지 않는다. 수동 기능 확인은 사용자에게 맡긴다. 실제 배포 시 소스·서비스·응답 확인 결과를 별도 영수증으로 남긴다.
