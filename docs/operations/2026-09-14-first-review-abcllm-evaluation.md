# 1차 검수의 abc-llm 대체 가능성 평가

**결론: 구현상 교체는 가능하지만 지금 전면 교체는 권하지 않는다. Claude를 유지하고, 대안은 GPT-OSS 120B부터 비교 운영한다.**

2026-09-14 03:53–04:32 KST 실측 완료. 운영 모델·설정·판정은 변경하지 않았다. 실측 200회, 운영 읽기 전용 조회, 코드 검토와 회귀 재현을 바탕으로 작성했다.

## 동일 입력 50건 × 4모델 실측 결과

200회 호출을 완료했다. 승인 25건·거부 25건의 **기존 관리자 판정과의 일치율**이며, 보류와 실패를 분모에서 제외하지 않았다. 모든 사례가 GitHub Pages인 편향과 연구 문서의 과거 승인 라벨 문제는 아래 한계에 명시했다.

| 모델 | 일치 / 50 | 일치율 (95% Wilson 구간) | 거부→승인 /25 | 승인→거부 /25 | 보류 | 호출 실패 | 중앙값 / p95 |
|---|---:|---|---:|---:|---:|---:|---|
| Claude Sonnet | 43 | 86% (73.8–93%) | 0 | 4 | 2 | 1 | 7.3초 / 12.1초 |
| Gemma 26B | 24 | 48% (34.8–61.5%) | 9 | 2 | 0 | 15 | 29.2초 / 60.0초 |
| Gemma 31B | 27 | 54% (40.4–67%) | 1 | 6 | 3 | 13 | 36.1초 / 60.0초 |
| GPT-OSS 120B | 41 | 82% (69.2–90.2%) | 5 | 4 | 0 | 0 | 11.8초 / 21.6초 |

정상 응답만 분모로 삼으면(보류 포함) Claude 43/49=87.8%, Gemma 26B 24/35=68.6%, Gemma 31B 27/37=73.0%, GPT-OSS 41/50=82.0%다. Gemma의 전체 일치율 하락에는 호출 실패와 판정 차이가 모두 기여했다. 성공 응답 기준 수치만으로 운영 성능을 평가하지 않는다.

지연은 재시도 없는 호출 1회 기준이며 실패의 대기 시간도 포함한다. 운영과 공유하는 게이트웨이에서 최대 2개를 동시에 호출한 관측값이다. CLI는 20초, abc-llm은 현재 2차 설정 그대로 60초까지 허용했다. 서로 다른 시간 예산을 숨기지 않고 아래에 명시한다.

| 모델 | 20초 초과 | 24초 초과 | 실패 코드 | 라벨과 다른 확정 판정 중 confidence≥0.9 |
|---|---:|---:|---|---:|
| Claude Sonnet | 0/50 | 0/50 | cli_error 1건 | 0건 |
| Gemma 26B | 30/50 | 29/50 | timeout 15건 | 10건 |
| Gemma 31B | 43/50 | 40/50 | timeout 13건 | 7건 |
| GPT-OSS 120B | 5/50 | 0/50 | 없음 | 4건 |

자기 보고 confidence는 정확도를 보증하지 않았다. 비용은 게이트웨이의 실제 원가/과금 자료가 없어 절감률을 산출하지 않았다. Sonnet 요청의 CLI modelUsage에는 `claude-sonnet-5`가 기록됐고 보조 `claude-haiku-4-5-20251001`도 포함된다. 응답 모델 ID는 원자료에 남겼다.

## 같은 판정을 2차 합의 규칙에 넣은 결과

**현재 `combineVotes` 순수 함수에 넣은 가상 재집계**다. 실제 운영에서 abc-llm 1차가 이미 2차로 연결된다는 뜻은 아니다. 현재 코드는 Claude 1차만 등록하므로 먼저 연결 변경이 필요하다. API 실패는 대기, 1차 실패는 2차 진입 전 실패로 계산했다. 실제 재시도·스케줄링과 공개 제품 재검수 경로는 재현하지 않았다.

| 1차 → 2차 | 합의 /50 | 합의 중 기존 라벨 일치 | 합의 중 거부자료 승인 | 사람 확인 | 2차 대기 | 1차 실패 |
|---|---:|---:|---:|---:|---:|---:|
| Claude Sonnet → Gemma 26B, Gemma 31B, GPT-OSS 120B | 14 | 13/14 (92.9%) | 1 | 15 | 20 | 1 |
| GPT-OSS 120B → Gemma 26B, Gemma 31B | 15 | 14/15 (93.3%) | 1 | 15 | 20 | 0 |
| Gemma 26B → Gemma 31B, GPT-OSS 120B | 15 | 14/15 (93.3%) | 1 | 15 | 5 | 15 |
| Gemma 31B → Gemma 26B, GPT-OSS 120B | 15 | 14/15 (93.3%) | 1 | 15 | 7 | 13 |
| GPT-OSS 120B → Claude Sonnet | 35 | 33/35 (94.3%) | 0 | 14 | 1 | 0 |
| Gemma 26B → Claude Sonnet | 14 | 14/14 (100.0%) | 0 | 20 | 1 | 15 |
| GPT-OSS 120B → Claude Sonnet, Gemma 26B | 20 | 18/20 (90.0%) | 2 | 14 | 16 | 0 |

GPT-OSS → Claude 조합은 이 표본에서 35건이 합의하고 거부 자료를 승인한 합의는 없었다. 여기에 Gemma 26B를 추가하면 낮은 확신/보류 제외 규칙 때문에 오히려 거부 자료 승인 합의가 2건 생겼다. 모델 수가 많다는 이유만으로 더 안전하다고 볼 수 없다. 전건 Claude 2차를 유지하면 Claude 호출 수 절감은 없으며, 비용 절감 효과를 주장하지 않는다.

합의율과 합의한 부분의 일치율은 서로 다른 지표다. 예를 들어 사람 확인·대기 건을 빼고 높은 일치율만 보고 전체 시스템 정확도로 해석하면 안 된다. 두 Gemma 모델의 오류가 독립이라고 가정하지도 않았다.

## 현재 운영 구조와 대체 가능성

2026-09-14 03:49 KST 읽기 전용 운영 조회:

- 1차: Claude CLI `sonnet`, `reviewMode=observe`. 관측 결과를 남기며 1차 결과 자체로 후보 상태를 바꾸지 않는다.
- 2차: abc-llm `[MLX] gemma4-26b`, `[MLX] gemma4-31b`, `[MLX] gpt-oss-120b`.
- 2차 설정: `agreeAt=0.7`, `includeAiHeld=true`, `sampleRate=0.05`. 일치 결과도 사람이 확정하며 공개 제품을 자동으로 내리지 않는다.
- 최근 24시간 1차 Claude: 성공 2,236, 실패 13(형식 오류 12, CLI 오류 1), 원본 변경으로 대체 5. 성공 지연 중앙값 6.1605초. 이 수치는 처리 안정성이지 판정 정확도가 아니다.
- abc-llm 모델 목록 API에서 현재 모델 존재를 확인했다. Qwen 등 목록의 다른 언어 모델은 이번 실측 대상이 아니며 성능 우열을 주장하지 않는다. 임베딩·음성 모델, heretic/uncensored 변형은 이번 1차 검수 비교 대상으로 선택하지 않았다.

공유된 `REVIEW_SYSTEM_PROMPT`, `ReviewInput`, `validateReviewOutcome`을 그대로 사용해 abc-llm을 호출하는 `reviewWithGateway`가 이미 있다. 이번 검수의 질문은 배포된 제품 URL의 적격성이다. 제작 도구 탐지의 정확도나 별도의 뉴스/카테고리 분류 정확도를 평가한 것은 아니다.

따라서 **개발상 대체는 가능하다. 그러나 환경변수의 모델명만 바꾸어서는 동작하지 않는다.**

## 2차에 주는 영향과 현재 안전장치

같은 모델의 이름이 같으면 중복 표는 이미 제외한다. 따라서 GPT-OSS를 1차로 옮기고 현재 2차 구성을 그대로 두어도 사용하는 서로 다른 모델은 네 개에서 세 개로 감소한다. 중복 호출 자체는 여전히 발생하며, 중복 모델이 실패하면 그 실패도 outstanding으로 집계되어 전체 합의가 대기한다. 설정에서도 그 모델을 빼거나 등록 전에 제거해야 한다.

이름만 다른 같은 모델은 현재 독립 표로 계산될 수 있다. `[MLX] gpt-oss-120b`와 `gpt-oss-120b`가 일치 표 두 개가 되는 순수 함수 재현을 확인했다. 실제 API는 요청 `[MLX] ...`와 다른 접두사 없는 모델 ID를 응답한다.

**합의는 모든 모델의 만장일치가 아니다.** 보류 표와 낮은 확신의 Claude 표는 제외된다. 이번 `skillberry-store`는 Claude가 reject(0.68), Gemma 31B가 needs_review, Gemma 26B·GPT-OSS가 approve였고, 실제 `combineVotes`는 승인 2표의 agreed를 반환했다. 잘못된 승인 방지가 우선이면 낮은 확신의 반대 의견이나 명시적 보류를 자동 제외하지 말고 사람 확인 대상으로 남기는 정책을 별도로 평가해야 한다. confidence 임계값을 모든 모델에서 무조건 없애는 것도 해법이 아니다.

실패/대기 표가 있으면 결과를 성급히 합의로 올리지 않고 대기하는 보호는 존재한다. 집계에 포함된 결정이 엇갈리면 사람이 보도록 하는 보호도 있다. 그러나 **서로 다른 모델이 동일한 입력을 봤다는 사실을 보장하는 보호는 보강이 필요하다.**

`reviewMode=enforce`를 함께 켜는 것은 별도 변경이다. 이 모드에서 1차가 승인하면 후보가 approved로 바뀌며, 현재 2차의 needs_review 대상 조건을 벗어난다. 공개 후 위험 신호/표본 검수가 있을 수 있지만 모든 1차 승인이 발행 전에 2차를 거치는 구조는 아니다. 따라서 모델 교체 검증과 발행 강제 조건 변경을 함께 진행하지 않는다.

## 비교 평가 설계와 한계

관리자 확정 기록 567건에서 저장소 이름의 고정 해시로 승인 25·거부 25건을 선택했다. 모델 간에는 같은 고정 입력과 현재 정책 프롬프트를 제공했다. 비교 모델은 Sonnet + 현재 운영 2차의 세 모델, 총 200회를 실행했다.

- 50건 모두 GitHub Pages이고 49건은 `host_excluded_subpath`로 규칙 검수가 보류한 사례다. 일반 도메인·SaaS·로그인형 서비스 전체를 대표하지 않는다.
- 관리자 라벨 47건은 9월 10일, 3건은 9월 9일에 생성됐다.
- 원래 관리자 스냅샷 50건 모두 pageText/readme가 없어 이대로 한 소량 연결 실험은 본 평가에서 제외했다.
- 현재 `loadReviewInput`으로 읽기 전용 입력을 재구성하고, 운영의 `fetchReadmeSample`과 동일한 함수로 README 48건을 보완했다. README 없음 2건, 요청 실패 0건. 운영 DB에는 쓰지 않았다.
- 저장된 페이지 본문은 승인 25건에 있고 거부 25건에는 없다. 페이지 수집 시각도 9월 9~10일이므로, 이 자료는 최신 페이지를 브라우저에서 독립 검수한 균형 정답셋이 아니다. 원문 읽을 수 있는 양과 판정 결과 사이에 편향이 있다.
- 기존 승인 라벨 `riskninja2026/research-reports`는 공개 연구 보고서 모음이다. 현재 정책의 제외 대상이므로 기존 라벨과 다르다고 반드시 모델 오류가 아니다.
- 따라서 실측 표는 **기존 관리자 판정과의 일치율**이다. 서비스 전체 정확도, 최신 정책의 진짜 정답 정확도, 미래 성능 보장으로 해석하지 않는다.
- 모델 자체의 confidence는 별도로 측정한다. 보류와 API/스키마 실패도 전체 분모에서 제외하지 않고 각각 보고한다.
- 단일 동결 입력과 temperature=0의 1회 결과이며, 반복 안정성이나 프롬프트를 바꿨을 때의 성능은 이번 수치에 포함하지 않는다.
- 두 모델을 한꺼번에 최대 2개 호출했다. 운영과 공유하는 게이트웨이에서 측정한 시간이라 독립 장비 성능이나 최대 처리량 시험은 아니다.

## 실제 재현/테스트

- 추가 운영 읽기 전용 점검(04:10 KST): 최근 미확정 2차 행 90개, 후보/입력 조합 30개는 모두 저장 해시와 현재 입력 해시가 일치했다. 입력 변경 결함의 재현은 가능하지만 이 표본에서 운영 오판 발생을 입증한 것은 아니다.
- 모델/제공자 교체 캐시 문제와 2차 등록 SQL 조건은 소스 검토로 확인했다. 실제 운영 데이터를 수정해 시험하지 않았다.

## 검토 결론

**현재는 Claude Sonnet을 유지하고, abc-llm 대안을 검증하려면 GPT-OSS 120B부터 비교 운영하는 것이 적절하다.** 검증한 세 대안 가운데 호출 안정성이 좋았지만, 문서 주소를 실제 서비스로 승인한 의미 오류가 확인되어 바로 발행 판단을 맡길 근거는 부족하다. Gemma 26B는 거부 자료를 승인하는 경향, Gemma 31B는 승인 자료 거부/보류와 긴 지연 때문에 이번 설정 그대로의 1차 교체 후보로 권하지 않는다.

먼저 모델 교체 없이도 적용할 수 있는 README 링크 보존과 2차 입력 일관성 문제를 수정하고, 낮은 확신의 반대 의견/보류를 무시하는 합의 정책을 검토해야 한다. 모델이 바뀌어도 입력 정보의 손실과 합의 정책의 빈틈은 남는다. 이 수정의 정확도 향상 폭은 별도 전후 실험이 필요하며 이번 보고서에서 수치로 보장하지 않는다.

## 구현한다면 나눌 변경 단위

- **PR 1 — 현재 2차 입력 일관성 수정.** 모델 교체와 관계없이 필요한 수정이다. 1차 시도/입력 스냅샷 연결, 입력 변경 시 폐기/재등록, 기록 시 상태 비교와 재현 회귀 테스트.
- **PR 2 — 1차 다중 제공자 지원.** provider/model 설정·검증·호출 분리, 제공자/정규 모델/시도별 캐시와 재시도, 2차 대상 조회 확장, 중복 모델 호출 제외. 기존 Claude/observe가 기본값.
- **PR 3 — 제한된 비교 운영.** 추천 후보를 실제 새 수집 자료에서 Claude와 비교만 하고, 지연/실패/부적격 승인/2차 대기량을 기록. 현재 정책으로 독립 확인한 정답셋에서 기준을 통과한 뒤 교체 범위 결정.

## 권장 진행 방식

1. 먼저 1차 제공자 지원과 2차 입력/시도 연결, 캐시/모델 식별을 구현한다. 후보 발행 정책은 observe로 유지한다.
2. 독립적으로 재검수한 최신 정답셋에 연구 문서·일회성 설문·설치형 제품·커버리지 문서와 실제 폼 빌더/연구 도구를 포함한다. 모델별 일치율보다 부적격 승인율을 우선 비교한다.
3. 대체 모델은 shadow 평가로 기존 Sonnet과 함께 기록하되, 같은 모델을 2차 독립 검수자로 중복 사용하지 않는다. Claude를 완전히 제거하는 조합과 Claude를 어려운 건/2차에 남기는 조합을 따로 평가한다.
4. 타임아웃/형식 오류를 거부 판정으로 만들지 않는다. 적격성은 미확정으로 유지하고 재시도 또는 별도 검수로 보낸다.
5. 교체는 정확도와 오류율·지연·2차 대기량을 함께 확인한 뒤 결정한다. 절대 비용 절감률은 abc-llm의 과금/운영 원가 자료 없이 산출하지 않는다.

예를 들어 부적격 25건에서 오승인이 0이어도 정확한 이항분포 기준 단측 95% 상한은 약 11.3%다. 1% 수준을 입증하려면 부적격 약 300건에서 0건 정도의 별도 확인이 필요하다. 50건 파일럿의 순위 차이만으로 전면 교체를 확정하지 않는다.
