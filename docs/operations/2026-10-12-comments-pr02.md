## 현재 목표와 완료한 작업

PR02의 작성 폼과 기존 E2E 선택자만 변경했다. 평소에는 약48px의 `댓글 남기기…` 버튼을 표시하고, 로그인한 사용자는 그 자리에서 작성창을 펼쳐 본문에 포커스를 받는다. 로그인 상태 조회 실패에는 `다시 확인` 버튼을 제공한다.

## 인터페이스와 설계 결정

`FeedbackForm({ slug, githubDeliveryAvailable })`와 POST 초안 계약을 유지했다. 성공 시 기존 `nmv:feedback-submitted` 일반 Event를 계속 발생시킨다. 접수 결과·목록 연결은 PR03에서 확장한다. 폼의 중복 `#feedback`, 제목, 바깥 테두리를 제거했다. 통합 영역의 `#feedback`은 상위 상세페이지에 한 번만 두도록 부모 작업에서 연결한다.

비로그인 작성 진입은 기존 `/login`을 사용한다. `nmv:feedback-write-intent:{slug}`에 임의 토큰과10분 만료 시간을 저장하고 `returnTo=/p/{slug}?feedbackCompose={token}#feedback`으로 이동한다. 기존 `safeReturnUrl`은 상대 URL의 쿼리와 해시를 유지한다. 복귀한 폼은 인증 상태·같은 프로젝트·해시·저장 토큰·만료 시간을 확인한 뒤 의도를 한 번 소비하고, `feedbackCompose`를 History API로 지운다. 저장소를 사용할 수 없으면 토큰 없이 `/p/{slug}#feedback`으로 복귀하고 사용자가 직접 작성창을 연다. 일반 로그인에는 일치하는 복귀 토큰이 없다. 기존 GitHub callback 실패는 원래 returnTo 없이 `/login?connectGithub=1&githubError=...`로 이동하므로 남은 작성 의도가 일반 로그인에 적용되지 않는다. 인증 앱·API·OAuth 동의·키·이메일 의존성은 변경하지 않았다.

기존 `nmv:feedback-draft:{slug}`의 유효한 제목·본문·requestId는 실제 편집 전까지 유지한다. 예전 폼에서 본문만 쓰고 제목을 비워 둔 초안은 기존 API에 접수될 수 없었으므로 파생 제목과 새 requestId로 복원해 등록 버튼이 잠기지 않게 한다. 실제 내용·분류·동의 변경이 있을 때만 새 requestId와 파생 제목을 만든다. 같은 칩을 다시 누르는 것은 편집으로 보지 않는다. 실패한 요청은 `nmv:feedback-retry:{slug}`에 해당 requestId를 기록하여 실제 문서 새로고침(`navigation.type=reload`)일 때 같은 초안을 다시 펼친다. 일반 로그인 후 같은 프로젝트를 방문할 때 남은 실패 표시만으로 펼치지 않는다. 재시도는 그대로 보관한 payload를 전송한다. 편집·취소·성공은 이 재시도 표시를 지운다.

파생 제목은 본문 첫 비어 있지 않은 줄에서 HTTP(S) URL 토큰만 제거하고 공백을 정리한 뒤120자 이내로 자른다. URL만 있는 줄은 `댓글`을 사용한다. 본문은 그대로 보존한다. 기존 `initialFeedbackReview`는 제목과 본문을 합쳐 URL이4개 이상이면 검토 상태로 접수한다. 제목에 첫 줄을 그대로 복사하면 본문 첫 줄의 URL2개가 총4개로 세어지는 영향을 코드 검토로 확인했고, 제목 생성에서만 중복을 방지했다. 검토 정책은 수정하지 않았다.

기존 E2E는 제목 입력 대신 작성 진입 버튼과 `댓글 내용`, `등록`을 찾도록 보정했다. 실패 후 새로고침·본문 보존·동일 requestId 재시도 시나리오는 유지한다. 댓글 목록의 상태 안내와 접수 결과가 같은 영역에 놓이는 경우를 위해 기존 접수 결과 문구로 상태 선택자를 좁혔다.

## 남은 작업과 다음 명령

부모가 상위 상세페이지의 통합 `#feedback`을 연결했다. 교차 리뷰에서 빈 제목 초안의 제출 잠김과 일반 로그인에서 남은 실패 표시로 자동 펼쳐지는 문제를 위와 같이 수정했다. PR03 접수 상태·재로그인·목록 갱신, PR04 GitHub 옵션과 전달 상태 축소는 담당 작업에 남겨 두었다. 현재 GitHub 옵션과 수신 미연결 안내는 기존 마크업이다.

사용자 수동 검증 항목은 비로그인 작성→GitHub 인증→같은 프로젝트 복귀와1회 펼침, 인증 취소·실패 후 일반 로그인에서 자동 펼침 없음, 로그인 상태 작성과 본문 포커스, 취소→재열기 초안 복원, 공개 동의와 본문 필수 조건, 레거시 초안의 변경 전 payload 보존, 실패→새로고침→동일 요청 재시도다.
