# 댓글 PR01 구현 기록

2026-10-12. 브랜치 `feat/comments-list-20261012`.

## 현재 목표와 완료 작업

확정된 댓글 시나리오의 PR01 범위만 구현했다. 상세페이지 댓글 헤더·전체/내 댓글 탭·작성 폼·목록을 기존 `FeedbackList`의 `children` 조합으로 연결했다. 기본 3개, 본문 두 줄, 글별 native `details` 펼침, 조회된 목록 더보기/접기를 적용했다. 작성자·분류·날짜·작은 원문 링크를 유지하고 큰 제목의 반복을 없앴다.

공개 GET은 기존 `feedback` 배열에 `total`을 추가한다. 공개 개수는 `accepted`, 제품이 `banned` 아님, 작성자 존재라는 목록과 같은 조건으로 집계한다. 기존 정렬과 공개 50개/내 댓글 100개 제한은 유지하며 제한에 닿은 목록은 최근 조회 범위를 표시한다.

공개와 내 댓글 조회는 독립적으로 성공·실패·초기 로딩을 처리한다. 공개 성공은 개인 조회의 네트워크 오류나 503에 가려지지 않는다. 개인 조회 오류는 내 댓글 탭에서 다시 불러올 수 있고 빈 목록 안내로 바꾸지 않는다. 개인 조회 401은 내 댓글을 지우고 전체로 돌아간다. 공개 개수는 초기/실패 시 `null`이며 0으로 보이지 않는다. 갱신 실패 시 이미 읽은 목록은 오류 안내와 함께 남는다.

## 주요 결정

- 새 client wrapper나 전역 상태는 만들지 않았다. `FeedbackList({ slug, children? })`는 헤더 다음, 댓글 목록 앞에 작성 폼을 둔다.
- `FeedbackItem`과 `FeedbackDeliveryStatus`의 기존 전체 표시 및 export는 바꾸지 않았다. 원문·관리자 화면에 본문 축약이 전파되지 않는다.
- `listProductFeedback(slug): Promise<FeedbackView[]>`는 기존 계약을 유지한다. GET은 새 `listProductFeedbackWithTotal(slug)`을 사용한다.
- 목록/개수는 `onPrimary` 안의 `repeatable read`, `read only` 트랜잭션으로 같은 시점의 공개 상태를 읽는다. outbox의 기존 `feedbackId` unique index가 목록의 left join을 한 행으로 제한하므로 집계는 제품·작성자 inner join만 사용한다.
- 순차 웹 배포 중 기존 GET `{ feedback }` 응답을 만나면 목록은 표시하고 개수는 `null`로 유지한다. 배열 길이를 전체 개수로 추정하지 않는다. 제공된 `total`이 잘못된 경우에는 조회 오류로 처리한다.
- 기존 `nmv:feedback-submitted` 재조회 이벤트 처리 방식은 유지했다. 접수 결과 전달·즉시 반영·갱신 경합 처리는 PR03 범위다.
- PR01 단독 상태에서는 `#feedback`을 기존 폼에 한 번만 유지한다. PR02가 폼의 ID를 없앨 때 페이지의 바깥 댓글 영역으로 옮긴다. 작성 폼의 자체 제목·테두리와 제작자 설정 링크는 후속 PR의 범위다.
- POST, DB 스키마, 인증, 플래그, 워커는 변경하지 않았다.
