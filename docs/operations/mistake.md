## 실수로 볼 지점

### 1. 화면 글이 제목뿐이면 제품이 아니라고 한다 — 73건

자바스크립트 앱은 보이는 글이 제목만 있는 경우가 많다. 기준은 그때 이름, 설명, README로 판단하고, 그 주소가 그 소프트웨어를 제공한다고 읽히면 승인한다.

예: `bubba8587/solenoid` (`https://solenoid-ngc.vercel.app`). 화면 글은 `Solenoid`뿐인데 README는 노드 그래프 계산기라고 기능을 적는다. 2차는 화면 글이 비었다며 거부했다.

### 2. GitHub Pages를 남의 사이트나 문서로 본다 — 81건

`owner.github.io/프로젝트`는 그 프로젝트의 홈일 수 있다. 기준은 호스트만으로 거부하지 않고, 그 페이지가 소프트웨어를 소개하는지 본다.

예: `0xmortuex/Vex` (`https://0xmortuex.github.io/vex-website`). 2차는 소프트웨어가 실재한다고 적고도 `*.github.io`라서 남의 플랫폼이라며 거부했다.

### 3. 별 500개 기준을 웹 페이지에 적용한다 — 39건

별 500개 이상은 배포 주소 없이 저장소만 보는 설치형 예외다. 웹 주소가 있는 후보의 승인 조건이 아니다.

예: `ilyautov/moysklad-mcp-ru` (`https://moysklad-mcp-ru.aifrontier.tech`). 페이지와 README는 MCP 서버의 기능을 설명하는데, 2차는 별이 2개라 설치형 예외를 못 채웠다며 거부했다.

### 4. 문서 도구로 만든 홈을 문서 본문으로 본다 — 14건

Docusaurus, VitePress, MkDocs, Sphinx, Just the Docs로 만들었다고 문서가 되는 것은 아니다. 그 페이지가 소프트웨어를 소개하고 설치나 시작 방법을 안내하면 홈이다. API 레퍼런스나 매뉴얼의 한 장만 문서 본문으로 거부한다.

예: `NeodymiumPhish/Pharos` (`https://neodymiumphi.sh/Pharos`). Just the Docs로 만든 페이지에 Overview, Features, Architecture가 있는데, 2차는 문서 사이트라며 거부했다.

### 5. 자기 제품의 마케팅 페이지를 제품이 아니라고 한다

소프트웨어가 있고 그 주소가 자기 페이지면 가격, 체험, 가입, 받기가 있어도 승인한다. 이 유형은 위 분류의 「그 외」 82건 안에 섞여 있고, 따로 세지는 않았다.

예: `Christophevanengelen/unfold` (`https://unfold-nine.vercel.app`). 7일 체험, 월 구독, 받기 버튼이 있는 Favorable 소개 페이지인데, 2차는 마케팅이라 소프트웨어가 아니라고 거부했다.

개인 프로필도 같은 종류의 어긋남이다. 한 사람의 이력, 포트폴리오, 개인 홈, 개인 블로그는 소프트웨어가 아니어도 승인한다. 이번 348건 분류에서 「개인 사이트」로 집계된 8건은 상담 판매 사이트와 섞여 있어, 8건 모두가 실수라고 단정하지 않는다. 같은 모델이 개인 홈과 이력서를 「쓸 수 있는 제품이 아니다」로 거부한 것은 앞선 사람 큐에서 확인했다. `JFWooten4/JFWooten4` (`https://wooten.link`), `VTrisac/Platform-cv` (`https://cv-victor-trisac.vercel.app`).

## 2차가 맞게 거부하는 지점

이 경우는 실수로 고치지 않는다.

- 가입이나 제품 설명 없이 로그인 폼만 있는 화면
- npm, PyPI, pub.dev, NuGet, RubyGems, Packagist, Docker Hub, Terraform Registry, GitHub 저장소 페이지처럼 남의 등록 사이트
- 강의, 부트캠프, 멤버십처럼 가르치는 것을 파는 페이지
- 사람 이름의 사이트라도 상담 예약과 요금만 있는 서비스 판매 페이지. 예: `Clickzou/vincentrousseauspy`
