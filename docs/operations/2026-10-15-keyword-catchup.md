## OSS 추가 실행에서 확인한 사항

첫 1제품 호출은 약 16.9초에 HTTP 200 / `gpt-oss-120b` / 정상 종료로 응답했다.
실제 사용량은 입력 1,850·출력 405토큰이었다. 기본 Python User-Agent의 edge403은
명시 User-Agent로 해결했다. 비공개 설정의 API 키를 실행 때만 읽는다.

여러 제품을 묶은 뒤, 제품 1개 단위로 줄인 요청에서도 익명 boolean 배열 개수가 틀렸다.
예를 들어 10개 키워드에 11개, 16개에 22개 판정이 반환됐다. 해당 결과는 모두 차단했다.
키워드 이름과 boolean을 한 쌍으로 명시하도록 응답 표현을 바꾸고, 원 키워드와 개수·순서·
문자열이 완전히 일치할 때만 기존 저장 형식으로 변환한다. 판정을 자르거나 채우지 않는다.
의미 판단 기준과 제공 근거는 유지한다. 첫 완성 묶음은 독립 의미 검토 뒤 저장한다.

추가 검증은 API 계약 fixture 10개, worker fixture 16개, multi watcher 17개,
v4 실행기 fixture 6개를 실제 통과했다. API 부분 응답·모델 불일치·사용량 오류·원문 외 인용과
키워드 누락·중복·순서 변경은 저장 단계에서 거절한다.

### 실제 의미 검증 뒤 OSS 자동 승인 중지

처음 5제품·68키워드와 다음 6제품·82키워드는 전체를 원문과 대조해 적합함을 확인하고,
공식 DB에 `gpt-oss-120b/abcllm`으로 저장했다. 이 11제품은 색인까지 확인했다.

이어 명확한 오역 사례를 원문 그대로 별도 QA에 넣었다. 제품30727의 원문은 대면 Werewolf/

`document summarizer`를 직접 표현이 없다는 이유로 거절했다. 원문은 편지를 쉬운 말로 설명하는
기능을 제공하므로 기존의 넓은 표현 허용 기준에 어긋나는 과삭제다.

두 오류를 확인한 즉시 OSS API 작업자만 중지했다. 미완성 묶음은 저장하지 않고 Codex 공유 큐로
돌렸다. 이미 전체 의미 검토를 통과한 11제품은 보존한다. 부분·QA 결과는 처리 완료에 합산하지
않는다. OSS의 단독 자동 승인은 재개하지 않는다. 두 사례는 이번 정책에서 발견한 실제 오류이며
모델 전체의 정확도나 오류율을 추정하는 통계로 사용하지 않는다.
