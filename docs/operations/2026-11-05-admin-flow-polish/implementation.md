# 운영 홈 정렬·실데이터 지표·업무 목록 추가 조회

## 반영 범위

- 넓은 콘텐츠 영역을 유지한다. 프로젝트 9단계의 번호·이름·수치·상태·추이 위치를 맞추고, 폭이 부족하면 흐름 영역 안에서만 가로로 이동한다.
- 선택 단계의 상세를 모델 설정·실제 사용, 담당·실행 관측으로 구분한다. 제어 영역은 내용 높이에 맞춘다. 기존 상태 글자 크기와 제어 동작은 유지한다.
- 전체 등록 프로젝트는 products의 현재 모든 상태를 센다. 공개 등재(seeded/verified), 검증 대기, 차단은 별도로 표시한다.
- 발행 추이는 crawl_publication_changes의 delta=1 전환 기록이다. 정확한 최근 1시간·24시간과 직전 24시간을 비교한다. 24개 시간 막대의 마지막 칸은 현재 시간의 부분 집계다. 수동 등록·현재 공개 재고와 다른 범위임을 표시한다.
- SNS 흐름은 실제 외부 글 수집 → 프로젝트 연결 → 화제 공개 조건 → 홈 대표 검토 → 사이트 노출이다. 홈 대표 검토는 별도 분기이며 외부 SNS 자동 송출 기능을 새로 만들지 않는다. 실제 공개 스위치와 수집기의 중지·정체·미확인을 구분한다.
- 후보 검수·사용자 요청·공개분 재검토 목록은 최초 30개, 추가 스크롤마다 다음 30개를 실제 서버 조회한다. DB 원문 시각의 마이크로초와 식별자로 경계를 보존하고, 검색·정렬 조건을 커서에 묶는다.
- 추가 목록을 보는 동안 자동 갱신은 ‘이전 목록 확인 중’으로 보류한다. 수동 갱신은 첫 30개부터 다시 읽는다. 선택 상세와 처리할 원본의 검증, CSV의 전체 필터 범위는 유지한다.

## 조회·보호 경계

공용 캐시·DB 이전·새 수집 잡·발행 동작·모델 호출은 추가하지 않는다. 새 GET 경로는 관리자 권한 확인과 private/no-store 응답을 사용한다. 요청 목록 JSON에는 연락처 이메일·원문·전체 처리 레코드를 싣지 않는다. 기존 처리 액션·CSRF·원본 판·DR fence를 유지한다.

## 검증 기록

- 통합 범위 13개 파일, 113개 회귀 검사 통과. 추가로 실제 피드백 상세의 문맥 누락을 수정하고 기존 요청 상세 10개 검사 통과.
- TypeScript와 변경 파일 ESLint 통과. 후속 수정은 변경 범위 검사와 필수 GitHub CI에서 검증한다. 수동 전체 DB·전체 단위 검사는 반복하지 않는다.
- 실데이터 읽기 전용 미리보기: 1600·1440·1280·768·390px에서 프로젝트 단계의 공통 행 위치와 페이지 가로 넘침 없음 확인. 새 지표·SNS는 1600·390px에서 읽기 실패·브라우저 예외·페이지 넘침 없음, 시간 막대 24개 확인.
- 실제 사람이 검수할 목록의 최근순·대기순·들어온 순·별 많은 순·최근/오래된 푸시순 6개 정렬에서 처음 30개와 아래 스크롤 뒤 60개를 확인했다. 처음 추가 GET 0회, 스크롤 뒤 1회이며 요청 완료만으로 연속 조회하지 않는다.
- 요청 목록 GET의 열린 요청·문의·사용자 글 전체·수정 요청 네 갈래 모두 HTTP 200, 실패 유형 없음. 실제 요청 데이터는 0~2개, 공개분 재검토는 14개여서 이 두 목록의 30개 초과 브라우저 검증은 실행하지 못했다. 경계·검색·권한·선택 상세의 범위 검사로 보완한다. 가상 데이터를 운영 DB에 넣지 않았다.
- 추가 목록의 자동 갱신 보류 및 수동 첫 30개 복귀를 브라우저 시험 시계로 확인했다. 데이터는 실제 복제본을 그대로 조회했다.

실행 영수증과 실패한 하네스·수정 전 결과는 `/tmp/admin-flow-polish-20261105`에 보존한다. 개발 미리보기의 관측을 운영 응답 시간이나 운영 p95로 해석하지 않는다. 병합·운영 배포 완료 여부는 실제 릴리스 영수증으로 별도 확인한다.

## 기존 전체 범위 정렬 한계

약 58.8만 전체 수집 후보에서 별 수·푸시 시각으로 정렬하는 조회는 이번 커서 투영 이전의 동일 SQL도 복제본의 8초 제한(SQLSTATE 57014)에 걸렸다. 이번 기본 최근 목록과 사람 검수 범위의 6개 정렬은 정상이다. CASE·조건부 조인·JIT 조정만으로 해결되지 않아 효과 없는 변경은 반영하지 않았다. 전역 DB 시간 제한·색인·스키마를 바꾸지 않았고, 전체 범위 메타데이터 정렬 구조는 별도 개선 항목으로 남긴다. 안전한 진단 기록은 `/tmp/worklist-sort-*.log`에 보존한다.
