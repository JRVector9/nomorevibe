# 심사 보완 및 운영 파이프라인 점검 — 2026-09-14

PR #113·#114·#115를 순서대로 검증·병합하고 최종 코드 `aa07228`을 웹 2대와 워커 5개에 배포했다. 수집 실패 12개 복구 및 새 1·2차 심사 저장을 실제 운영 데이터로 확인했다.

## 보완 내용

- README의 실제 앱/데모/문서 링크 목적지를 심사 입력에 보존한다. HTTP(S), 길이 제한을 적용하며 저장소 내용을 명령으로 취급하지 않는다. 기존 캐시는 버전으로 구분해 재수집하고, 동시 갱신된 원본을 오래된 응답으로 덮지 않는다.
- 2차 심사마다 정확한 1차 시도 ID와 근거 리비전을 연결한다. 모델 호출 전과 결과 저장 트랜잭션에서 다시 확인한다. 원본 변경, 새 1차 판단, 종료된 심사, 교체된 워커 임대에 뒤늦은 결과를 기록하지 않는다.
- 낮은 확신의 반대 의견이나 명시적 보류도 사람 확인으로 남긴다. 알려진 `[MLX]` 별칭, 같은 모델의 중복 응답은 독립 표로 세지 않는다. 관리자 집계에도 동일 규칙을 사용한다.
- 1차 성공 캐시·재시도 예산·강제 심사 승인 조건을 공급자/모델에 맞춘다. 실제 1차 호출은 Claude/sonnet을 유지한다. abc-llm 1차 전환 기능을 완성했다는 뜻은 아니다.
- 공개 프로젝트의 2차 표본이 첫 25개에 머물던 문제를 회귀 테스트로 재현하고 수정했다. 새 1차 판단의 등록과 이전 심사 종료를 후보 잠금 아래 함께 처리한다.

초기 실패를 숨기지 않았다. 원래 작업 폴더에서는 이번 범위 밖의 ProductHero 변경으로 단위 테스트 1개가 실패했다. 배포에서 제외한 깨끗한 코드에서는 전체 통과했다. 모델 바인딩 강화 후 기존 테스트의 가짜 공급자 `test`를 실제 `claude-cli` 및 명시적 테스트 모델로 맞췄다. 새 회귀 테스트는 수정 전 README/합의/캐시/세대/공개 표본 문제를 재현했다.

`review` 스킬의 필수 체크리스트가 설치 및 대체 경로 모두 없어 해당 공식 절차는 완료하지 못했다. 변경 코드 직접 검토와 위 회귀·통합 검증을 수행했으며 독립 에이전트 리뷰로 보고하지 않는다.

## 운영 중 추가 발견 및 보완

GitHub 실패 12개 모두 수동 HTTP 확인에서 `301`이었다. 주소 변경을 정상적으로 따라가야 한다는 [GitHub 공식 문서](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api#follow-redirects)와 실제 응답을 확인했다. 기존 `redirect:error` 때문에 이를 transport 오류로 기록했다.

PR #114는 `https://api.github.com` 내부 이동만 최대 3회 허용한다. 외부 호스트·HTTP 하향·인증정보 포함 URL·루프·빈 목적지를 거부하고 전체 타임아웃과 중간 응답의 API 할당량 제한을 유지한다. 수정 클라이언트로 12개 모두 실제 `200` 및 동일 저장소 ID를 확인했다. 이름이 바뀐 저장소의 스타/근거 API 요청에도 공통 적용된다. 단위 테스트 969개 통과, PR CI도 통과했다.

PR #113 배포 후 새 1차 성공과 입력 바인딩 정상(555행 중 누락/불일치 0)을 확인했지만, 이전 프롬프트의 판단을 2차에 올린 뒤 입력 검사에서 닫는 작업이 새 심사 앞에 쌓였다. PR #115는 최신 1차의 프롬프트·규칙·유효기간을 큐 상한 적용 전에 검사하며, 바인딩 없는 과거 대기 및 만료된 대기를 모델 호출 전에 종료한다. 완료된 과거 의견은 보존한다. 회귀 실패 2개를 확인한 후 관련 DB 통합 39개 및 타입/린트가 통과했다.

추가 모델 호출 없이 앞선 평가의 동일 200개 응답에 새 합의 규칙만 적용했다. 현재 조합(Claude 1차 + abc 3모델)의 합의는 14건에서 11건, 사람 확인은 15건에서 18건으로 바뀌었다. 대기 20건, 1차 실패 1건은 그대로다. 알려진 Skillberry 오승인 합의는 사람 확인으로 바뀌고 새 합의 11건은 과거 관리자 라벨과 일치했다.

## 운영상 남아 있는 제한

- Claude 1차 observe 모드를 유지한다. 모든 발행이 AI 승인 후에만 이뤄지는 enforce 모드로 전환한 것이 아니다. 모델 교체도 하지 않았다.
- abc-llm 2차의 확률적 형식 오류/타임아웃은 남아 있다. 실패를 합의 표로 사용하지 않으며 재시도/사람 확인 경로로 남긴다.
- AI 근거 재검사 및 스타 갱신은 진행형이다. 수집·평가 작업이 실행된다는 증거와 모든 항목의 정확성/최신성을 보장한다는 주장은 다르다.
- 별도 작업 중인 ProductHero·뉴스 시안은 이번 배포 범위에 포함하지 않았다.
