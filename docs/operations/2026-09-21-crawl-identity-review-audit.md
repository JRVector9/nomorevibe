## 발견한 문제와 수정

- 발견 큐가 GitHub 저장소 대소문자를 구별했다. 같은 저장소의 동시 검색 결과는 정렬된 트랜잭션 잠금으로 직렬화하고 최초 발견 기록을 유지한다. 자동 재수집, 관리자 근거 재수집, 거절 재심사도 같은 잠금과 중복 조건을 사용한다.
- 설치형만 저장소까지 중복 검사하고 웹 제품은 URL만 검사했다. 이제 모든 자동 판정·심사·발행에서 저장소와 기존 URL을 함께 확인한다. 배포 주소가 바뀌어도 기존 제품/차단을 우회하지 못한다.
- 발행 직전 존재하지 않는 행은 행 잠금으로 보호되지 않았다. 저장소 잠금을 먼저 잡고 최종 중복 확인 및 후보 발행 전환을 제품 생성과 같은 트랜잭션에서 실행한다. 제품 등록/저장소 변경도 같은 잠금에 참여한다.
- 1차 심사의 규칙 거절 사유가 모두 `not_a_product`로 덮였다. 서버가 확인한 `already_listed`/`banned` 등 원래 사유를 유지한다. 발행 중 중복이 발견된 경우에도 기존 제품 링크/상태를 기록한다.
- 거절 재심사 계획 생성 후 제품이 등록되거나 다른 대소문자로 수집되면 적용 시 다시 확인해 건너뛴다. 관리자 판단과 변경된 원본은 기존 CAS 보호를 유지한다.
- migration0043은 저장소 식별 조회에 표현식 인덱스 두 개를 추가한다. 인덱스 전 운영 저장소 조회는 17,012행 전체 스캔, 113ms였다.

과거 `already_listed` 기록은 중복 제품이 아니라 **중복 등록을 차단한 이력**이다. 이를 발행 완료로 바꾸면 신규 발행 통계가 부풀려지므로 기존 제품 링크로 연결하고 상태 이력을 보존한다. 메이커의 별도 제품이 같은 모노레포를 참조하는 경우까지 전역 유일 제약으로 금지하지는 않는다. 이번 중복 방지는 자동 수집·발행의 저장소 단위에 적용된다.
