# AI2 GPU3090 주 모델과 abcLLM 대체 모델

사용자 지정 구성은 GPU3090 직접 연결 우선, 기존 abcLLM Supa 대체 경로다. 현재 운영 적용 전이다.

| 항목 | 주 모델 | 대체 모델 |
|---|---|---|
| provider | `local-direct` | `abcllm` |
| 모델 | `qwen3.8-flash-next` | `[supa] Qwen3.8-27B-NVFP4` |
| 추론 경로 | `http://100.77.43.63:8090/v1/chat/completions` | 기존 abcLLM API |
| 실제 엔진 문맥 한도 | 50,000 | 98,304 |
| 요청 입력+출력 상한 | 32,000 | 32,000 |
| 출력 최대 | 10,000 | 10,000 |
| thinking | 비활성화 | 비활성화 |

실제 메시지와 chat template를 해당 엔진의 `/tokenize`로 계산하고 출력용 10,000을 남겨 입력은 22,000까지 허용한다.
시스템 지시문과 생성 시작 template도 포함한다. abcLLM 별칭은 실제 Supa 엔진
`Inferact/Qwen3.8-27B-NVFP4`의 tokenizer에 명시적으로 대응한다. 검증 실패와 초과 입력은 추론 전에 차단한다.
출력 10,000을 반드시 생성하라는 뜻은 아니다. 실제 긴 입력의 60초 추론 제한 충족 여부는 아직 실측하지 않았다.

직접 계약은 `AI2_DIRECT_SERVING_CONTRACTS`, abcLLM 계약은 기존 설정의 선택적 `requestBudget`에 넣는다.
선택적 필드가 없는 기존 계약의 hash와 전송 형식은 보존한다. 용량 장부는 요청 상한으로 축소하지 않는다.
GPU는 기존 `gpu3090-qwen`, Supa는 기존 `supa` 물리 그룹을 공유하여 별칭에 따른 중복 점유를 막는다.

주 모델 자리가 15초 이상 없거나 전송 전 검증이 실패하면, 현재 설정·입력·행·소유권·단계를 다시 확인하는
트랜잭션에서 아직 보내지 않은 요청만 철회하고 대체 행을 만든다. 모델 실패 판정과 검수 완료로 기록하지 않는다.
이미 전송했거나 완료 여부가 불명확한 요청은 점유를 보존한다. 완료된 주 모델 응답의 내용이 유효하지 않으면
기존 대체 검수 절차로 이어진다. 응답 제한시간 후의 불명확한 호출은 별도 종료 증거 없이 대체 추론을 보내지 않는다.

## 실제 검증

- 직접·abcLLM·not-started 전송: 4파일 50개 통과.
- 설정·호환 전송·기존 판정·스키마: 5파일 57개 통과.
- 관측 artifact/replay: 4파일 213개 통과.
- 실제 PostgreSQL 직접/대체 결과 저장·terminal 정산·이전 migration 호환: 7파일 50개 통과.
- 실제 PostgreSQL 대기 전환·문맥 변경 rollback·전송/불명확 보존·tokenizer 실패·예약/대기 실제 조회: 2파일 20개 통과.
- 최종 consumer/lifecycle/CI 파일 배치: 6파일 137개 통과.
- 관리자 화면/선택 보존: 3파일 48개 통과.
- TypeScript와 변경 56개 파일 ESLint(warning0), diff-check 통과.

검사 간 중복이 있어 고유 총수로 합산하지 않는다. 전체 수동 suite/build는 PR별 범위 검증 정책에 따라 실행하지 않았다.
입력 22,000 허용/22,001 차단은 HTTP 테스트 서버로 검증했다. 실제 GPU의 32,000토큰 부하 시험은 미실행이다.
기존 [Tailscale 시험](2026-10-25-gpu3090-tailscale-test.md)의 305ms 합성 응답은 실제 제품 검수 완료 증거가 아니다.

## 운영 적용 순서

기존 AI2 정체로 정규 배포 진행 관문도 막힌다. 필수 CI/main 이미지와 additive0132 이전을 검증한 뒤,
별도 기록을 남기는 단일 AI2 복구 배포로 기존 abcLLM 설정의 실제 검수 진행을 회복한다.
정상 진행 관문 확인 후 기본 `npm run deploy -- plan|run`으로 전체 대상 앱을 갱신한다.
모든 설정 소비자가 새 provider를 읽을 수 있게 된 뒤, 설정 판 비교와 용량 정책 변경으로 직접 주/abc 대체 경로를 적용한다.
다른 검수 정책·감사 보류·수동 판정·자동화 허용값은 보존한다.

운영 완료 조건은 설정/이미지/계약 일치, 직접 검수 결과 저장과 terminal 정산, 실제 abcLLM 연결 확인 및 전체 관문 통과다.
현재 이 운영 완료 조건은 미확인이다.
