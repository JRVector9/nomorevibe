# GitHub 반복 탐색 축소와 탐색 계측

검수 대기열 정책 PR 다음에 적용하는 별도 변경이다. 두 PR은 개별 검증·커밋하고, 배포는 통합 검증 뒤 한 번에 진행한다. 이 변경에서 운영 설정·배포·기존 데이터는 수정하지 않는다.

## 원인과 적용

`seedFrontier`는 과거 전체 탐색이 하루 이상 뒤처졌을 때 별도의 최신 탐색을 배정한다. 기존 최신 탐색은 신호마다 첫 페이지만 보고 한 시간 뒤 다시 최근 `windowDays`(기본 3일)를 확인했다. 따라서 시간당 반복 범위가 크다. 과거 전체 커서도 결국 이 구간에 도달한다. 커밋·토픽 검색 간 동일 저장소와, 한 저장소의 서로 다른 커밋도 별도 검색 결과로 나온다. 이 코드 조사로 운영의 전체 중복률 중 경로별 비율을 확정할 수는 없다.

선택: 검색어를 없애거나 이미 수집한 저장소 전체를 검색에서 제외하지 않고, 최신 탐색의 다음 구간을 지난 확인 끝 시각부터 이어간다. 검색 색인 지연에 대비해 직전 5분만 겹쳐 확인한다. 기존 신호·근거와 전체 탐색의 완전성 책임을 유지하면서 반복 구간을 줄이기 위한 선택이다.

- 첫 최신 탐색은 기존대로 최근 3일이다. 다음 확인은 예를 들어 `00:00` 확인 뒤 `01:00`에 `전날 23:55~01:00`만 검색한다.
- 장기간 중단 후 최신 구간은 기존 windowDays로 제한한다. 그 이전 구간을 따라가는 과거 커서는 보존한다.
- 저장된 미완 페이지·다른 신호는 기존 구간을 마친 뒤 새 구간으로 넘어간다. 토큰·API 제한 시 저장 위치에서 재개한다.
- 최신 탐색은 첫 페이지 미리보기다. 결과가 100개 이상인 구간을 전체 탐색에서 완료한 것으로 간주하지 않는다. 과거 커서를 건너뛰거나 완료 처리하지 않는다.
- 페이지 안에서 저장소 대소문자만 다른 동일 SHA·동일 귀속 근거는 한 번만 처리한다. 서로 다른 SHA·귀속 근거는 보존한다.

5분은 선택한 재확인 구간이며 GitHub의 색인 완료 보장이 아니다. 5분보다 늦게 반영되는 항목을 최신 미리보기에서 즉시 발견하지 못할 수 있고, 날짜상 해당 구간의 과거 전체 탐색이 이를 나중에 확인할 수 있다. 이미 완료한 전체 구간의 늦은 색인을 전부 복구한다는 보장도 없다. 반복 검색을 완전히 없애기 위해 중첩을 0으로 만들지는 않았다.

## 기록과 해석

관리자 크롤러 활동의 최근 회차·시간별 누적에 다음 항목을 추가한다.

- `returned`: 새 API 응답의 항목 수(최대 100개 처리 범위). DB 커서에 저장한 페이지를 이어 처리하면 0이다.
- `filtered`: 잘못된 저장소 키·배포 URL 없는 저장소 검색 결과 등 조건 미달 제외 수.
- `pageDuplicates`: 페이지 안의 동일 저장소·SHA·귀속 근거 중복 제외 수.
- 기존 `examined`, `existing`, `discovered`: 실제 처리 항목·기존 또는 충돌로 미삽입·실제 신규 적재 수. 서로 다른 커밋이 같은 저장소를 가리키면 existing에 포함될 수 있다.

구조화 서버 로그 `crawl.seed_page`에는 신호, 검색 종류, 최신/과거, 실제 창·페이지, 응답·필터·중복 수를 남긴다. `crawl.seed_batch`에는 같은 구분과 실제 처리·기존·신규 수를 남긴다. 신호·구간별 신규 발견률을 비교하기 위한 자료다. 로그에는 커밋 본문·토큰·원응답을 남기지 않는다. 상세 로그는 DB의 마지막 12개 회차 이벤트를 밀어내지 않도록 logger에 직접 남긴다. 관리자에는 기존 안전한 숫자 투영만 전달한다.

대기열 상한 도달과 신규 적재 5분 예산 대기를 따로 표시한다. `rateCapped`를 엄밀한 최근 1시간 제한처럼 표시하던 문구도 바로잡는다. API 조회와 DB 저장은 다른 시점에 일어날 수 있으므로 회차별 returned와 examined는 같지 않을 수 있다. 이 숫자를 고유 저장소 총수나 모든 중복 유형의 정확한 분해로 해석하지 않는다.

## 남은 검증과 다음 단계

검증: 두 변경을 합친 관련 회귀 161개(10파일), Next typegen 후 전체 TypeScript, 변경 파일 ESLint, `git diff --check` 통과. 저장 페이지 재개·신호별 구간 유지·과거 커서 보존·장기 중단·계측 누적과 관리자 표시를 확인했다. 로컬 DB 통합 명령은 global setup의 migrate 단계에서 실패했으며 본문 테스트는 실행되지 않았다. 전용 DB `127.0.0.1:55435` 직접 연결도 `ECONNREFUSED`로 확인했다.

두 PR 통합 시 전용 DB에서 고유 미완료 저장소 집계·timeout·100만 건 규모 비용을 확인해야 한다. 현재 환경에는 전용 테스트 DB와 PostgreSQL 실행 파일이 없으며 Docker 접근 불가가 앞선 작업에서 확인됐다. 이번 변경에서 운영 DB에 부하용 행을 적재하지 않는다.

배포 뒤 같은 시간 범위의 신호·최신/과거별 신규 발견률과 검색 응답 수를 비교한다. 현재는 실제 운영 중복률 개선이나 3,000건/시간 달성을 측정하지 않았다. 검색어 간 중복과 최신/과거 간 중복은 여전히 남으며, 이를 완전히 차단하면 새로운 AI 제작 근거를 놓칠 수 있다. 다음 조정은 측정된 발견률에 따라 검색 빈도와 예산을 조절하되 기존 구간·근거를 보존하는 방식으로 진행한다.
