# 모델 배정의 「동시에」 전환과 저장 결과

2026-11-13 관리자 화면의 선택 모델 승계, 저장 응답, 최근 실행 표시를 수정했다.

## 확인한 원인과 변경

- `/admin/flow` 단계 패널은 실행 방식만 바꾸고 분산 구성원을 채우지 않았다. 사유 번역의 기존 `m1-gemma`가 선택에서 빠지고 빈 목록 검증으로 확인 버튼이 잠겼다. 이제 순위대로 → 동시에 전환은 현재 순위 초안을 그대로 구성원으로 제안한다. 편집 중 바꾼 순위도 유지한다.
- 기존 분산 구성을 다시 편집할 때는 그 구성을 유지한다. 순위에서 새로 전환할 때는 보관된 예전 분산 구성보다 현재 순위가 우선한다. 같은 연결·모델의 칸 수는 재정렬과 중복 횟수를 고려해 이어 쓰고 새 구성원은 1칸으로 제안한다. 보관된 자동 칸 수 구성은 자동을 유지한다. 확인·저장 전에는 DB를 바꾸지 않는다.
- 응답이 끊겨도 서버에서 저장됐을 수 있는데 단계 패널은 「서버에 닿지 않았다」「저장 못 함」으로 단정했다. 단계 패널과 모델 서랍이 공통 저장 처리로 응답 불명과 서버의 명시적 거절을 구분한다. 불명 응답 뒤 후속 쓰기를 중단하고 자동 재시도하지 않는다. 모든 결과에 새 데이터 읽기를 요청하며, 불명 결과를 닫을 때는 페이지를 새로 읽는다.
- 작업 목록의 최근 1시간 비교는 순위 저장 시각만 고려하고 분산 설정 변경 시각을 무시했다. 이제 실행 방식·구성원 변경 시각도 반영한다. 변경 전 호출이 섞인 동안 새 구성의 정상 동작이나 특정 구성원 미사용을 단정하지 않는다. 실패·미확정·꺼진 연결 신호는 계속 표시한다.
- 저장 성공은 설정 저장의 확인으로 표시한다. 새 구성의 실제 호출 성공과 구분한다.

## 운영 읽기에서 확인한 범위

root의 2026-11-13 19:59~20:02 UTC 읽기 전용 증거에서 migration 0179의 `reserve_ranks`·`max_slots` 컬럼은 모두 존재했다. 사유 번역 실행 설정 행과 해당 분산 저장 성공 감사는 없었다. 당시 사유 번역은 기존 순위 설정을 사용했고 최근 작업 성공 시각은 있었으나, 이는 새 분산 설정의 실행 증거가 아니다.

사용자가 모델을 직접 고른 뒤 본 원래 저장 실패의 정확한 문구·선택 모델은 아직 확보하지 못했다. 따라서 그 서버 저장 실패의 근본 원인까지 확정하거나 운영에서 새 분산 호출이 성공했다고 주장하지 않는다. DB 스키마·운영 설정·모델 요청·배포는 변경하지 않았다.

## 검증

- 범위 unit: `model-assignment-save`, `models-unified-tasks-feedback`, `llm-task-assign-view`, `stage-panel`, `models-unified-tasks`, `stage-panel-model` — 80개 통과.
- 기존 runtime 회귀: `task-pool-concurrent`, `reason-translation-gateway-native` — 52개 통과. 구성원별 칸 수·업무 분산·예비 및 사유 번역 호출 계약을 모의 의존성으로 검증했다.
- 로컬 브라우저 fixture: 기존 사유 번역 모델 승계 → 확인 → 모의 저장의 task/mode/member/maxSlots/refresh 검증, 편집 중 순위 변경 후 동시에 승계, 저장 뒤 응답 끊김의 불명 표시·재편집 차단·페이지 새로 읽기. 모든 HTTP는 차단하고 서버 쓰기는 모의 함수로 대체했다.
- 변경 파일 ESLint, Next route typegen 뒤 `tsc --noEmit --incremental false`, `git diff --check` 모두 통과했다. 첫 타입 검사에서 route typegen 전 `PageProps` 부재와 신규 fixture의 `maxSlots` 누락을 확인해 typegen·fixture 보완 뒤 재검증했다. 첫 범위 회귀의 신규 fixture `M1` import 누락도 보완해 다시 통과했다. 전체 unit·전체 DB·종합 검사는 실행하지 않았다.

필수 GitHub CI는 실제 실행 결과로만 판정한다. 계정 billing 한도로 시작하지 못한 검사를 통과로 기록하지 않는다.
