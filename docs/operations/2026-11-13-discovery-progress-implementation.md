## 실제 검증

Node.js **24.18.0**, PostgreSQL **17 + pgvector 0.8.6**을 사용했다. 테스트 DB는 이 작업에서 새로 만든 `nmv-discovery-20261113-test-pg` 컨테이너다. 기존 개발·테스트·운영 DB는 가리키지 않았다.

- 변경 관련 단위·회귀 **13개 파일 152건 통과**: 기존 수집·근거·최신 탐색, HTTP 경계·취소, discovery 예산·한도·진척·캐시 계약, 네트워크 본문 제한.
- 전용 DB 통합 **3개 파일 31건 통과**: crawl-seed 20건, 공유 탐색 9건, 진척 저장 2건.
- Next.js route type 생성 성공. 전체 타입 검사와 변경 파일 10개의 ESLint도 통과했다. 상세 결과는 [validation.json](evaluations/2026-11-13-discovery-progress/validation.json)과 원본 로그로 보존한다.
- 큰 응답 재현은 합성 자료를 사용했다. 3,376,129바이트의 100개 커밋 응답을 실제 공유 검색 저장 경로로 통과시켰다. 별도 동일 fixture 투영은 23,556바이트였고, DB 검사에서는 64KiB 미만의 요약만 남고 원문·개인 이메일이 사라지는 것을 검사했다. 8MiB 경계 수용·초과 스트림 취소, 초과 원본의 claim 해제도 검사했다.
- 한 검색어 지속 실패 중 다른 검색어의 다음 날짜 전진, v2 완료 신호 이행, 부분 페이지 재개, 비활성화/재활성화, 정렬 변경, 미완료 큐 포화, 최신 탐색 장기 중단 후 중간 날짜 보존을 검사했다.

초기 실패 로그도 삭제하지 않았다. 기존 테스트의 전체 신호 장벽 가정은 새 독립 진행 동작에 맞춰 바꿨다. 대형 커밋 캐시 fixture는 기존 128KiB 파서 보호 정책에 맞춰 한 개의 거대 메시지 대신 100개 메시지로 구성했다.

## 운영 반영과 남은 실측

push·PR·병합·이미지 게시·배포는 실행하지 않았다. 운영 DB 마이그레이션이나 커서 초기화도 실행하지 않았다. 현재 프로젝트의 로컬 수정·검증 범위를 따랐다.

새 SQL 마이그레이션은 없지만 저장되는 작업 커서는 v3다. 향후 배포에서는 주·예비 crawler가 같은 구현을 사용해야 한다. v3를 저장한 뒤 구버전으로 되돌릴 때에는 현재 커서 백업과 변환 방안을 준비해야 하며, 초기화로 미완료 작업을 버려서는 안 된다. 필수 GitHub CI와 공식 배포 절차는 별도 운영 반영 시 수행한다.

운영 반영 후 동일한 완전한 60분 창에서 신규 고유 저장소 수, 검색어별 완료 날짜, 최신 탐색 지연, 반복 실패, 신규/기존 비율, 후속 검수 적체를 비교해야 한다. 이번 로컬 검사로 시간당 1,500건 회복이나 운영 메모리·처리율 개선을 검증한 것은 아니다. 1초 구간도 8MiB를 계속 넘는 실제 사례가 남으면, 캐시 키·페이지 완료 판정까지 함께 바꾸는 페이지 크기 축소를 후속으로 다룬다.
