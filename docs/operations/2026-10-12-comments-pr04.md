# 댓글 PR04 — GitHub 옵션·전달 상태·설정 메뉴 통합

2026-10-12. PR03 기반으로 폼·목록·헤더 연결 완료. 부모 에이전트의 코드 리뷰·최신 PR03 수정 반영·필수 CI·PR 공개·병합과 사용자 직접 기능 확인은 남아 있다.

## 현재 목표

서비스 댓글을 기본으로 두고, GitHub 수신이 연결된 프로젝트에서만 접힌 전달 옵션을 제공한다. 별도 공개 동의와 기존 전달 상태를 유지하면서 상세페이지의 공간을 줄인다.

## 완료한 작업과 수정 파일

- `components/product-detail/FeedbackGithubOptions.tsx`: `selected`, `consent`, `onChange({ sendToGithub, githubDisclosureConsent })`, 선택적 `disabled`를 받는 클라이언트 컴포넌트. 기본 접힘, 복원된 선택은 펼침, 선택 변경 시 별도 동의를 해제한다. 선택한 경우에만 필수 공개 동의를 표시하며 접수 중 입력·펼침 변경을 잠근다.
- `components/product-detail/FeedbackDeliveryStatus.tsx`: `feedback`, 선택적 `compact`를 받는다. 기본값은 기존 전달 문구·확인된 이슈 링크·외부 상태·오류 코드 표시를 유지한다. `compact`에서는 `local_only`의 중복 접수 문구와 내부 오류 코드를 생략하며 나머지 전달 상태와 확인된 이슈 링크·외부 상태는 표시한다.
- `components/product-detail/FeedbackSettingsMenu.tsx`: `slug`를 받아 기존 `/p/{slug}/github`로 연결하는 작은 네이티브 `details` 메뉴. 서버에서도 사용할 수 있고 설정 페이지의 권한 검증은 변경하지 않는다.
- `components/product-detail/FeedbackForm.tsx`: 연결된 프로젝트에서만 접힌 옵션을 표시하고 일반 미연결 안내는 제거했다. 접수 안내는 `compact` 전달 상태를 사용한다. 종류 버튼·서비스 공개 동의 라벨은 최소44px 높이로 보완했다.
- `components/product-detail/FeedbackList.tsx`: 기존 전달 상태를 새 모듈에서 다시 내보내 원문·관리자 소비자를 유지한다. 상세페이지의 공개 일반 댓글은 중복 상태 줄을 생략하고, 검토 중·공개 거절의 비공개 안내와 GitHub 전달 상태·확인된 이슈 링크를 작은 상태 줄로 표시한다. 헤더에 선택적 `settings: ReactNode` 슬롯을 추가했다.
- `app/p/[slug]/page.tsx`: 유효한 GitHub 저장소가 있는 프로젝트의 수신 설정 링크를 댓글 헤더 메뉴로 옮겼다. 폼을 목록의 `children`으로 두며 `#feedback` 앵커는 한 번만 유지한다.

## 주요 결정

- 옵션 컴포넌트는 부모가 `githubDeliveryAvailable`인 경우에만 렌더링한다. 전달 여부와 동의는 부모의 기존 초안에 저장하며 자동 선택하지 않는다.
- GitHub 전달이 선택된 저장 초안에서 현재 연결이 없어도 복원 시 전달 값·제목·본문·requestId를 그대로 보존해 동일 요청 재시도를 유지한다. 이 초안에만 작은 `GitHub 전달 선택 해제` 버튼을 표시한다. 사용자가 실제로 편집하거나 해제하면 전달 값·별도 동의를 함께 해제하고 기존 `change`를 통해 새 requestId를 만든다. 동의가 없는 숨은 선택 때문에 댓글 작성이 계속 막히지 않도록 해제 버튼을 제공하며, 접수 중에는 부모 fieldset으로 잠근다.
- 공개 이슈는 작성자 계정이 아니라 앱 봇 명의이며 닉네임·제목·댓글·원문 링크가 전달된다고 별도로 안내한다.
- 네이티브 `details`의 기본 키보드·펼침 접근성을 사용한다. 작은 메뉴와 선택 라벨은 최소44px 높이이며 긴 동의 문구는 좁은 화면에서 줄바꿈된다.
- 전달 상태 컴포넌트는 `FeedbackView`를 타입으로만 가져온다. 서버의 기존 링크 검증·outbox·워커 계약은 변경하지 않았다.
- 접수 안내의 `GitHub에는 전송되지 않았습니다.` 문구는 기존 E2E 확인 계약을 유지한다. 목록의 `local_only`에서는 중복 문구와 구분자를 모두 생략한다.
- 설치된 Next.js의 `use-client`, 서버·클라이언트 컴포넌트, `Link`, `page`, CLI `typegen` 관련 가이드를 읽었다. 기존 초안 초기화·제목 생성과 PR03의 목록 접수 순서 처리는 변경하지 않았다.
