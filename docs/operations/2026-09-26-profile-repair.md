# 검색 프로필 갱신과 기존 데이터 복구

`source_hash`는 실제 키워드를 생성할 때 모델에 준 `profileEvidence`의 SHA-256이다. 최신 원본 해시로 값을 덮어쓰는 것은 복구가 아니다. 원본이 바뀌면 `needs_refresh`가 켜지고 실제 생성에 성공할 때만 새 해시와 키워드가 함께 저장된다. 실패하면 이전 키워드와 생성 해시를 보존한다.

## 재발 방지

- 제품 이름, URL, 갈래, 소개, 설명, 토픽, 본문, README 변경을 DB 트리거가 감지한다. 감사 심사 메모의 추가·변경·삭제도 감지한다.
- 원본 변경은 재시도 한도를 초기화하고 `source_revision`을 증가시킨다. 진행 중 작업이 동일 밀리초의 변경을 놓치지 않게 한다.
- 결과 저장 시 제품 및 프로필 행을 잠그고 최신 심사 메모를 다시 읽어 생성 입력 해시를 대조한다. 변경된 입력에 대한 이전 응답은 저장하지 않는다.
- 갱신 중인 프로필은 검수하지 않는다. 검수 결과 저장 시에도 최신 입력 해시와 생성 당시 해시를 대조한다.
- 잘린 본문 뒷부분만 바뀌어 실제 모델 입력이 같으면 기존 정상 키워드를 재사용한다. 명시적으로 복구 대기시킨 빈 프로필은 다시 생성한다.
- 기존 worker의 동시 호출 2개와 느린 응답 시 심사에 양보하는 제한을 유지한다.

## 실행

운영 마이그레이션 `0048_search_profile_freshness`를 먼저 실행하고 새 text worker를 배포한다. 같은 운영 DB를 쓰는 서비스에 마이그레이션은 한 번만 적용한다. 운영 환경 변수를 화면이나 파일에 출력하지 않는다.

```sh
node scripts/migrate.mjs
node --import tsx scripts/reconcile-search-profiles.ts
node --import tsx scripts/reconcile-search-profiles.ts --apply --retry-invalid-output --retry-empty
```

기본 실행은 읽기 전용이다. `queued`는 대기열에 넣을/넣은 건수이며 실제 재생성 완료 건수가 아니다. `--retry-invalid-output`은 이전 생성/검수의 한도 초과를 다시 볼 수 있게 한다. `--retry-empty`는 이전 스키마에서 빈 객체를 성공으로 저장했을 가능성이 있는 빈 프로필을 한 번 다시 생성한다. 복구 버전 1을 프로필에 기록해 같은 빈 응답/한도 초과를 반복 재개하지 않는다. 실제로 근거가 없는 제품은 새 엄격한 파서에서도 명시적인 빈 배열이 정상일 수 있다.

복구 후 읽기 전용 대조를 반복하여 `mismatched`가 없어졌는지, `alreadyPending`, 생성 `error_code`, 검수 `verify_error`와 `verified_at`을 확인한다. 동적 원본이 계속 바뀌면 갱신 대기 중인 불일치는 일시적으로 존재할 수 있다. 완료한 프로필은 최신 입력과 해시가 일치해야 한다.

## 검증 기록

원본 변경, 심사 메모 변경, 재생성 실패의 해시 훼손을 실제 PostgreSQL 테스트에서 먼저 재현했다(3개 실패, 기존 7개 통과). 수정 후 별도 PostgreSQL 17 인스턴스에서 마이그레이션 전체 적용 및 생성/검수 통합 22개 통과. 복구 dry-run, 멱등적인 대기열 등록, 빈 프로필 실제 재생성, 이전 실패의 재개, 검수 중 입력 변경을 포함한다. 전체 검증과 배포 결과는 PR 및 CODEX_HANDOFF.md에 후속 기록한다.
