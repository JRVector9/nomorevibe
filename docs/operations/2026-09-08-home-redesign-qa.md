# 메인 페이지 리디자인 적용·QA 보고 — 2026-09-08

포트 3200에서 확인한 메인 페이지 시안을 현재 `origin/main` 기반의 독립 작업 브랜치에 옮겼다.
원본 작업 폴더의 미커밋 인증·상세·Compose 변경은 포함하지 않았고, 메인 페이지에 필요한 화면·조회만
현재 워커 구조 위에 적용했다. 로컬 production 이미지의 확인 주소는 `http://127.0.0.1:43201`이다.

## 적용 범위

- 공통 헤더·푸터, 검색, 모바일 하단 탐색
- 소개 영역과 최근 출시·제작 도구·관심 분야·업데이트 요약 카드
- 큰 썸네일을 사용하는 프로젝트 카드, 최신·관심·저장소 링크 필터, 카테고리·제작 도구 필터
- 브라우저 로컬 저장 목록과 상세 페이지 왕복
- 집계 기준을 설명하는 native dialog
- 정적 선별 AI 소식 영역. 실시간 피드가 아님을 화면에 표시한다.
- KST에서 끝난 날짜 구간만 쓰는 홈 집계와 표본 부족 상태 표시

제작 도구는 메이커가 등록했거나 수집 제품을 클레임한 경우만 공개 뷰모델, 카드, 검색, 필터,
집계에 사용한다. 수집기가 추정한 과거 값은 DB에 남아 있어도 메인 페이지에서는 숨긴다. 저장소 URL은
공개 라이선스를 뜻하지 않으므로 `오픈소스` 대신 `저장소 있음`으로 표시한다.
관심 증감률은 고유 방문 수집 시작 시점부터 직전·최근 7일 구간을 모두 채운 경우에만 계산한다.
구간을 채웠지만 상승 분야가 없는 상태와 아직 수집 중인 상태도 서로 다른 문구로 표시한다.

## QA 중 바로잡은 문제

- 카드 저장 버튼의 기준 요소가 없어 화면 위치에 따라 썸네일 밖으로 나가던 CSS를 수정했다.
- 순위에 없는 제품을 헤더에서 검색하면 결과가 비던 경로를 공개 최신 목록 검색으로 연결했다.
- 중복 쿼리 파라미터가 들어오면 `trim is not a function`으로 500이 나던 입력 처리를 보강했다.
- SSR에서 열린 dialog가 실제 modal 상태가 아니어서 Esc와 포커스 제어가 깨지던 문제를 수정했다.
- 카드 링크의 존재하지 않는 `#product-screen` fragment를 제거했다.
- 저장 목록에서 미클레임 별도 목록이 다시 나타나던 상태 결합을 한 목록으로 정리했다.
- 모든 경로의 skip link가 존재하는 `#main`으로 이동하도록 공통 레이아웃을 수정했다.
- `BETA` 텍스트 대비를 WCAG AA 기준 이상으로 높였다.
- 기존 추정 제작 도구가 카드·검색·필터·통계에서 확정 정보처럼 쓰일 수 있던 조건을 차단했다.
- 제품별로 생성되는 방문 해시를 분야 전체 고유 방문자로 설명하던 문구를 실제 집계 단위인
  `제품별 고유 방문의 분야별 합계`로 바로잡았다.
- 실제 `/go` 관심 정렬을 `저장 많은 순`으로 부르던 탭 문구를 `관심 많은 순`으로 수정했다.
- 초기 hydration 전에 정렬 링크를 누르면 공통 헤더가 새 쿼리의 숨은 입력을 먼저 렌더해 서버 HTML과
  달라지던 문제를 재현했다. 헤더의 URL 의존 마크업은 hydration 이후에 반영하도록 수정했다.
- 직전 7일 구간의 일부만 수집하고도 방문 100건을 넘으면 증감률이 조기에 노출될 수 있던 조건을
  차단했다. 두 비교 구간을 모두 수집해야 계산하며, 상승 분야가 없을 때는 수집 중이라고 쓰지 않는다.
- 기존 관리자 E2E가 남은 수집 frontier 때문에 재실행 시 흔들리던 fixture 정리를 보완했다.

단위 테스트 로그의 rate-limit·분류 실패, 통합 테스트 로그의 lease-loss·작업 실패는 해당 실패 경로를
검증하는 테스트가 의도적으로 만든 로그이며 전체 명령은 exit 0으로 끝났다. 첫 린트는 Playwright와
동시에 실행해 Playwright가 `test-results`를 교체하는 순간 해당 폴더를 읽지 못했다. 브라우저 테스트가
끝난 뒤 린트를 단독 재실행해 통과했다.
관심 지표 설명을 추가한 첫 E2E에서는 두 번째 dialog가 URL을 정리하기 전에 검색을 시작해 대기 시간이
초과됐다. dialog 닫힘과 `metric` 제거를 기다리도록 동기화한 뒤 전체 E2E 6개를 다시 실행해 통과했다.
hydration 진단 스크립트의 첫 실행은 CommonJS 출력에서 top-level await를 써 변환에 실패했다. 실행부를
함수로 감싼 뒤 개발 빌드에서 서버·클라이언트 DOM 차이를 확보했고, 수정 후 빠른 전체 이동 10회와
production 전체 흐름 10회를 반복해 같은 오류가 없는 것을 확인했다.
자동 전체 diff 리뷰는 30분 넘게 결과를 반환하지 않아 중단했고, 통과 판정으로 기록하지 않았다.
대신 수동 검토에서 관심 지표의 수집 구간 문제를 찾아 수정한 뒤 위 전체 검사를 다시 통과했다.

로컬 브라우저에서는 desktop 홈, 네 집계 카드, 최신 탭, 저장 유지와 저장 목록, 저장소 링크 필터,
제작 도구 자동 제출, 집계 기준 dialog, GET 검색, 제품 상세 이동, 관리자 로그인 경로, 390px 모바일
탐색과 가로 넘침을 확인했다. 최종 캡처는 `/tmp/nomorevibe-home-applied-final.png`와
`/tmp/nomorevibe-home-applied-mobile.png`에 있다.

## 로컬 운영 상태와 한계

`nomorevibe-workers-local-app`은 새 `nomorevibe-web:local-home-qa` 이미지로 포트 43201에서
실행 중이다. scheduler, crawler, reviewer, publisher, maintenance 다섯 워커도 각각 healthy 상태다.
웹은 테스트 전용 `nomorevibe_workers_local_deploy` DB를 쓰며 표시 데이터는 합성 fixture다.

이 작업은 로컬 적용 검증이다. 프로덕션 서버·도메인·DB와 장기 Claude 자격 증명은 `PENDING.md`의
P0가 정해진 뒤 별도 런북으로 배포해야 하며, 현재 결과는 외부 수집을 포함한 24시간 운영 증거가 아니다.
