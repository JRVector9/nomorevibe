# 프로젝트 제목·문구·설명 정리

## 변경
- GitHub 주소의 owner/repo와 정확히 같은 대체 제목만 repo로 표시. 예: `chamber-orchestra/metadata-bundle` → `metadata-bundle`. 원본 DB 이름과 검색 대상은 유지하고 홈·인기 목록·상세의 공개 뷰에서 일관되게 표시한다. 임의의 슬래시가 들어간 제품명은 유지한다.
- 프로젝트 카드·인기 구간·인기 전체 표의 설명을 최대2줄로 표시. 전체 소개는 title과 상세에서 확인 가능.
- 수집 과정을 설명하는 문구를 제거하고 실제 숫자·출처 배지·오류 상태만 간결하게 표시.

## 저장·↑ 숫자는 일주일 후 어떻게 되는가
- 저장은 이 브라우저 localStorage의 `nmb-saved-v1`에 저장한다. 만료 시각이 없으며 주가 바뀌어도 유지한다. 사용자 해제나 브라우저 데이터 삭제 시 없어진다. 로그인 계정 간 동기화는 아니다.
- 저장 화면의 별도 제한: 현재 저장 화면은 서버가 조회한 순위·미클레임 목록 안에서 저장ID를 필터링한다. 저장ID를 직접 조회하는 구조가 아니어서 조회 범위 밖의 오래된 저장 항목은 화면에 누락될 수 있다. 저장 데이터 만료와는 별개이며 이번 요청은 동작 설명으로 처리했다.
- ↑숫자는 투표수가 아니라 NoMoreVibe에서 제품으로 이동한 유효 방문 수다. 버튼이 아닌 표시용 span이다. 봇과 동일 방문자의10분 이내 반복 요청을 제외한다.
- 최신·저장소 목록 및 미클레임 카드: 최근7일 유효 방문 수. 매주 일괄0으로 만드는 방식이 아니며7일보다 오래된 방문이 빠지면서 감소할 수 있다.
- 주간 순위 카드: 해당 시즌 유효 방문 수. 주간 정책은 한국 시간 월요일00:00에 새 시즌이 시작하며 이전 시즌 기록은 보관한다.
- 누적 탭: 코드상 최대3650일 방문 집계다. 주간 초기화와 무관하다.
- 프로젝트는 일주일이 지나도 삭제되지 않는다. 순위 참여 범위는 시즌의 정책에 따라 바뀔 수 있지만 최신 목록·검색·상세는 공개 상태를 유지한다.

## 검증과 배포
단위3·통합11 통과, TypeScript/관련ESLint/diffcheck 통과. 격리된 운영 빌드와 인기 목록 브라우저3개, 최종 검색·상세 브라우저4개 통과. 독립 Codex 리뷰 CLEAN(추가 지적 없음, 원시 confidence 미제공).

초기 브라우저 검사에서 첫9개 밖에 있는 제목 fixture를 기대한 오류와 갱신 상태의 남은 집계 중 문구를 발견해 수정했다. 기존 미커밋 사용자 Hero를 포함한 작업 트리 검사는 cover12px로 실패했으므로 배포할 Hero만 사용한 격리 검사로 최종 검증했다.
