# 공개 제품 번역 언어 변경 — 2026-11-13

공개 제품의 번역 대상을 **영어·중국어 간체·일본어**로 정리한다. 중국어 한 종류를 고르는 선택은 기존 `/zh-Hans` URL과 번역을 재사용하는 간체로 결정했다. 한국어 소개는 기존 별도 경로를 사용한다.

## 동작과 보존

- 언어 메뉴와 SEO 대체 언어는 한국어·영어·간체·일본어를 표시한다. `/ja`는 노출된 공개 제품의 소개·설명만 요청한다. 전체 카탈로그 일괄 번역은 추가하지 않는다.
- 번체 신규 수요와 신규 dispatch를 차단한다. 워커의 대기 선택·예약 복구와 운영 대기 집계에서 번체를 제외한다. 관리자 기본 실패 목록/확인함도 활성 언어만 센다.
- 번체 원문·번역·대기 행·시도 횟수·기존 호출 장부는 삭제하거나 다른 언어로 바꾸지 않는다. 관리자에서 `중국어 번체 (보관)` 필터로 볼 수 있고, 재요청은 차단한다. 이미 전송된 호출은 기존 검증/정산 계약을 유지한다.
- 기존 번체 공개 주소는 경로와 쿼리를 유지하여 간체로 308 이동한다. 관리자·API 등 접두어가 붙은 비공개/기계 주소를 정상 엔드포인트의 별칭으로 만들지 않는다.
- 일본어 결과는 가나를 포함한 일본어로 검사한다. 제품명·숫자·보호 토큰·URL·인용 보존 조건은 계속 적용한다.
- 일본어가 포함된 모델 묶음에만 일본어 지시를 추가한다. 기존 영문/중문 묶음의 프롬프트 바이트는 유지한다.

## 번역량의 의미

번체 대기분은 자동 처리 대상에서 빠지지만 **번체를 일본어로 대체하면 비한국어 대상 언어 수는 여전히 3개**다. 일본어 방문 수요에 따라 새 항목이 생기므로 장기 총량이 반드시 줄어든다고 보장하지 않는다. 운영 DB의 현재 언어별 건수나 예상 절감량은 이번 작업에서 측정하지 않았다.

## 일본어 UI 범위

제품 내용, 공통 탐색·오류·카드 문구와 주요 목록·상세 문구는 일본어를 사용한다. 계정·정책·상세 보조 문구의 미번역 항목은 영어 카탈로그를 명시적으로 상속한다. 일본어 전체 UI 번역이 끝났다는 의미는 아니다. 모든 키와 치환 인자는 기존 다국어 계약 검사로 확인한다.

## DB 및 적용 순서

`0184_japanese_product_translation`은 번역·원문 언어와 알림 언어 CHECK에 `ja`를 추가하고, native product-translate 장부의 논리 키·멤버·dispatch·terminal·event 규칙 다섯 가지를 추가한다. 기존 장부 규칙은 그대로 유지한다. 생성 스크립트는 다음과 같다.

```sh
node --import tsx scripts/ops/generate-japanese-product-translation-sql.ts
```

적용 전 규칙 baseline 존재 여부를 검사하고, 추가된 다섯 규칙의 개수와 SHA-256을 확인한다. 임시 전용 PostgreSQL에서 실제 전체 마이그레이션과 일본어 native 왕복을 검증했다. 운영 반영 시 DB 마이그레이션이 먼저 필요하고, 웹·text 및 실제 배치 담당 앱을 공식 배포 scope/plan으로 확정해야 한다. 이 브랜치는 운영 DB·설정·서비스를 변경하지 않았다.

## 실제 검증

- 관련 단위/회귀 검사: 13개 파일, 고유 268건 통과. 최초 묶음의 번체 URL 기대값 실패는 새 간체 이동 정책을 검사하도록 고치고 해당 파일을 재실행했다.
- 관련 DB 검사: 기존 제품 번역 장부 4건, native 호출/기록 19건, 합계 23건 통과. 새 일본어 검사는 실제 loopback tokenizer/chat 응답으로 예약→dispatch→settled·결과 저장·ACK를 확인하고, 번체 행의 바이트 단위 보존·대기 제외·관리자 보관 필터·운영 대기 수 제외를 확인한다. 실제 외부 모델 품질을 측정한 검사는 아니다.
- `next typegen`, TypeScript, 변경 TypeScript/TSX 및 추가 파일 ESLint, `check:i18n`(4언어·9namespace·19공개 페이지), `git diff --check` 통과.
- 로컬 브라우저 화면 검증은 미완료. 연결된 `node_modules`가 Turbopack root 밖에 있어 기본 dev 실행이 실패했다. webpack 대체 실행에서는 instrumentation의 Node 내장 모듈 해석 오류가 났고, 임시 additional-root 실행도 런타임 패키지 해석 오류로 끝났다. 임시 개발 설정은 복구했다. 실패 화면을 정상 미리보기로 제공하지 않는다.
- 전체 unit·전체 DB·프로덕션 build·GitHub CI·운영 배포·운영 관측은 실행하지 않았다. 실패 및 재실행 로그는 작업 scratch 폴더에 보존한다.
