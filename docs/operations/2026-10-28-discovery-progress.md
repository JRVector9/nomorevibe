# 최신·전체 탐색 진척과 운영 계측

M3는 최신·전체 탐색을 유지하고 Oracle 한국어 탐색은 별도 consumer로 추가한다. 이 변경은 공통 탐색 작업 PR을 선행 조건으로 삼으며 배포·활성화 기록이 아니다.

`runDiscoveryBudget`는 두 경로가 준비됐을 때 페이지 예산을 50:50으로 나누고, 첫 경로에 남은 실행시간의 절반을 배정한다. 다음 회차에서는 시작 경로를 바꾼다. 한 페이지 설정도 교대로 진행한다. 실제 사용 페이지를 확인한 뒤 남은 몫을 다른 경로에서 사용하며, 공통 admission·인증 제한을 만나면 같은 회차의 추가 호출을 멈춘다. 마지막 실제 페이지 진척 시각이 1분 이상 차이나면 오래 기다린 경로를 먼저 실행하되 양쪽의 기본 몫은 유지한다. 하나의 외부 요청이 회차 실행시간을 넘기는 경우 그 회차에 양쪽 모두 진척할 수는 없으므로 다음 시작 순서를 함께 저장한다.

`recordDiscoveryProgress`는 서버·최신/전체/한국어·검색 신호별로 `operations_observations` 한 행을 원자적으로 누적한다. 작업 위치나 성공한 빈 회차를 처리량으로 세지 않는다. 검색 요청, 방문 페이지, 응답 재사용, 반환 항목, 실제 처리 항목, 기존 저장소, 신규 적재, 페이지 내부 중복, 한국어 yes/no/unknown을 구분한다. 검색 문자열·커밋 본문·자격 정보는 관측값에 넣지 않는다. 관측 저장 실패가 후보 적재 결과를 되돌리거나 검색 실패 원인을 대체하지 않는다.

키 형식은 `discovery-progress:<latest|full|korean>:<sha256(worker) 앞16자리>:<sha256(signal) 앞24자리>`이며 기존 varchar(80)에 들어간다. Oracle의 새 권한 프로필은 `korean` 키와 값만 허용한다. 전체 관측 목록과 워커 진행 판정에서는 이 누적 행을 제외해 큰 JSON을 일반 운영센터 응답에 싣지 않는다.

관리자 운영센터의 크롤러 활동에 서버·신호별 진척 표를 추가한다. 새 읽기는 복제본 전용·15초 캐시·3초 문장 제한이며 실패할 때 주 DB로 우회하지 않고 미확인으로 표시한다. 최대 최근 관측 512개까지만 표시하고 잘렸으면 그 사실을 알린다. 최근 약 1시간 수치는 1분 묶음 61칸이므로 실제 60~61분 범위다. 서로 다른 검색어의 같은 저장소는 각각 탐색 노력으로 센다. 고유 신규 적재량이나 엄밀한 최근 1시간 API 청구량과 혼동하지 않는다.

완료 날짜는 모든 페이지·분할 구간이 끝난 경우에만 전진시킨다. 현재 작업 구간, 완료 날짜와 현재 시각의 차이, 마지막 실제 진척, 미완료 시작 시각, 대기열 상한·적재 한도·GitHub 대기·인증·불완전 검색 사유를 별도로 표시한다. 과거 탐색의 날짜 차이가 크다는 사실만으로 워커 장애를 판정하지 않는다. Oracle 언어 확인 실패는 비한국어 제외와 분리해 재시도 수로 표시한다.

검증은 예산 공유·한 페이지 교대·남은 예산 재사용·시간 소진·공통 제한·지연 경로 우선 단위 회귀, 관측값의 범위·노출 통제·실패 격리·관리자 렌더 회귀, 전용 DB에서 동시 관측 누적·미완료 범위 보존을 포함한다. 로컬 DB를 사용할 수 없으면 통합 검사 성공으로 기록하지 않으며 GitHub 필수 CI에서 확인한다.
