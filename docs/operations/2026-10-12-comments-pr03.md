## 목표와 완료 작업

POST가 반환한 실제 댓글을 작성창 안내와 목록에 즉시 반영한다. `accepted`는 작성창을 접고 전체 목록으로, `held`·`rejected`는 작성창을 접고 내 댓글로 이동한다. 거절된 동일 요청의 재조회도 `공개되지 않음`으로 안내한다.

기존 제출 이벤트에 `{ feedback, replayed, created }`를 전달한다. `created`는 응답이 201이고 replay가 아닌 경우다. 목록은 ID로 중복 제거하며, 공개 개수가 이미 알려져 있고 신규 댓글 ID를 아직 확인하지 않은 경우에만 한 번 증가시킨다. 이후 GET의 `total`로 다시 동기화한다. 알 수 없는 개수를 0이나 배열 길이로 채우지 않는다.

각 목록 조회는 앞선 조회를 중단하고 세대 번호를 확인한다. 늦은 GET이나 컴포넌트가 제거된 뒤의 응답이 새 접수 결과를 덮지 않는다. 갱신 실패는 목록 오류로만 표시하고 이미 받은 댓글은 유지한다. 내 댓글 GET의 401은 작성자 목록을 비우며, 정상 GET은 현재 계정의 서버 목록으로 교체한다. 다른 작성자의 새 접수 결과가 들어오면 이전 작성자의 내 댓글도 합치지 않는다.

POST 시작 전에 초안과 동일 requestId의 재시도 표시를 저장한다. 접수 중 새로고침이나 결과를 받지 못한 경우 같은 요청을 다시 확인할 수 있다. 실패하면 초안과 작성창을 유지하며, 내용이 실제로 바뀔 때만 기존 편집 경로에서 새 requestId를 만든다. 로그인 만료·CSRF 만료는 초안을 즉시 저장한 뒤 기존 로그인과 프로젝트별 작성 의도 nonce로 돌아오게 한다. 접수 중 편집·취소·중복 제출을 막으며, 이동 시 POST 응답의 화면 반영을 중단한다.

PR02의 검토 보정도 전달받아 함께 반영했다. 빈 제목 때문에 API에서 접수될 수 없던 과거 초안만 제목을 복구하고 새 ID를 사용하며, 유효한 과거 제목·ID는 유지한다. 실패 초안의 자동 펼침은 실제 새로고침에만 적용하고 일반 로그인 복귀에는 작성 의도 nonce를 요구한다.

기존 UI 계약에 맞춰 Form/List의 작은 글자도 최소 13px로 맞췄다. 부모 에이전트가 PR01·PR02에도 같은 보정을 적용한다.
