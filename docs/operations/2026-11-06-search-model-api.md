# 검색 모델 API 설정

## 현재 실행과 관리자 설정

제품 벡터와 검색어 벡터는 같은 벡터 공간을 사용한다. 기본 모델은 기존 `bge-m3-f16@daec91ff`(1024차원)이며, 설정이 아직 없으면 각 프로세스의 기존 `EMBEDDING_URL`을 사용한다. 재정렬은 기존 `RERANK_URL`을 사용한다. 기본 환경변수 경로를 관리자 순위가 없다는 이유로 미설정으로 표시하지 않는다.

`/admin/models/search`는 실제 실행에서 읽는 API 연결을 설정한다. API 주소·키·모델 목록의 등록은 기존 AI 연결 관리 기능을 사용한다. 검색 설정에서는 등록된 API 연결의 모델을 선택한다. API 키는 서버 메모리에서만 복호화하며 브라우저·감사 기록에 반환하지 않는다.

## 벡터 호환성과 저장

제품·검색어 벡터는 하나의 설정으로 저장한다. 선택한 연결에 대해 현재 문서 해시와 일치하는 기존 BGE 벡터 32개를 다시 임베딩해 차원과 최소 코사인 유사도를 확인한다. 최소 유사도 0.999를 통과해야 설정을 저장한다. 제품·검색어 설정은 한 트랜잭션으로 바뀌며 별도로 서로 다른 모델을 선택할 수 없다.

이 검사는 저장된 벡터와의 호환성 관측이다. 원격 서버의 모델 파일 SHA를 직접 읽거나 파일의 불변성을 증명하지 않는다. 기존 BGE와 호환되지 않는 새 임베딩 모델로의 변경·전체 벡터 재생성은 이번 설정 기능의 범위가 아니다.

관리자 저장은 사이트 쓰기 관문·설정 판 비교·작업 잠금·연결 판 재확인·감사 기록을 거친다. 저장 후 웹과 text 워커가 동일한 DB 설정을 읽으며, 프로세스 스냅숏 갱신 주기 안에 새 요청부터 반영한다. 진행 중인 요청의 연결은 바꾸지 않는다.

## 상태 해석

관리자 페이지는 현재 적용 출처, API 주소, 모델, 모델 목록 응답, 확인 시각과 저장된 제품 벡터 현황을 구분해 표시한다. 모델 목록 응답은 임베딩·재정렬 추론 성공이나 전체 검색 성공을 의미하지 않는다. 설정 저장의 벡터 호환성 검사는 실제 임베딩 응답을 사용한다.

명시적으로 저장된 연결이 꺼져 있거나 키를 열지 못하거나 제품·검색어 설정이 서로 다르면 해당 벡터 호출을 사용하지 않는다. 환경변수로 몰래 대체하지 않는다. 검색은 기존 오류 처리에 따라 낱말 검색으로 내려가며, 제품 벡터 잡은 저장하지 않고 이후 틱에서 재시도한다. 재정렬이 실패하면 기존 섞은 검색 순서를 유지한다.

벡터·재정렬 요청은 기존과 같이 공통 모델 용량 장부를 거치지 않는다. 다른 모델 화면의 `실행 0`으로 이 서버의 실행 여부를 판단하지 않는다. API 주소는 웹과 text 워커 모두에서 접근할 수 있어야 한다. 관리자 웹에서 모델 목록을 읽었다는 사실만으로 모든 워커의 네트워크 접근을 확인했다고 표시하지 않는다.

호환성 기록은 선택한 연결의 판·주소·모델 이름에 묶인다. 연결을 편집해 판이 바뀌면 기존 기록을 그대로 신뢰하지 않으며 검색 모델 설정에서 다시 호환성을 확인하고 저장해야 한다. 모델 목록의 단순 다시 읽기는 기존 연결 편집 기능과 동일하게 연결 판을 올리지 않는다.

재정렬 설정을 저장할 때에는 모델 목록 확인에 이어 고정된 짧은 문장 쌍으로 `/v1/rerank`의 실제 응답 형식을 검증한다. 이 검증도 페이지를 여는 것만으로 실행하지 않는다. `MODEL_SERVING_CONTRACTS_DB=0`으로 DB 모델 설정 읽기가 명시적으로 꺼진 프로세스에서는 환경변수 경로를 현재 적용 출처로 표시하고 새 검색 설정 저장을 막는다.
