# NoMoreVibe — 1인 관리자 운영 기능 검토

2026-10-13. gpt-6.1-sol / xhigh 서브에이전트 3개가 콘텐츠, 운영·자원·복구, 사용자·권한·댓글·분석을 독립 검토했다. root는 결과를 합치고 핵심 결함의 page/action/domain 경로를 재확인했다. 감사 대상은 PR406 head `4a9a227`과 그 정상 merge `ca2c8c3`의 동일한 코드다. 운영은 후속 홈 RSC 교정 PR407/main `b5924ac`까지 13개 core 앱 배포와 런타임 검증을 완료했다. 추가 하단 AI 탭 교체 PR408/main `707e9c2`는 양웹 운영 배포와 네 언어 실제 노출·집계 대조를 완료했고 관리자 백엔드에는 변경이 없다. 최종 공개 릴리스는 아래 배포 기록을 따른다.

**현재 기능을 새로 만드는 것보다, 기존 기능에서 혼자 처리할 수 없는 마지막 동선을 연결하는 것이 우선이다.** 수집·심사·발행·차단/해제·감사·설정·작업 로그·검색 품질 지표는 이미 있다. 관리자 접근, 누락된 일의 발견, 공개 댓글 사후 조치, 번역 실패와 관측 완료 설명이 부족하다.

이 문서는 기능 검토와 다음 PR 제안이다. 아래 관리자 기능 전체를 이번에 구현했다는 뜻은 아니다. 운영 다국어 배포의 실제 명령·DB·이미지·13개 core 앱 결과는 [배포 기록](2026-10-13-public-i18n-production-rollout.md)과 구분한다. 세 담당자는 코드와 문서만 읽었고 브라우저 기능 시험·운영 DB·키·외부 API에 접근하지 않았다. root의 배포 전후 읽기 검증과 환경 조치는 별도 증거로 기록한다.

## 먼저 확인한 관리자 접근 문제

- root가 쿠키 없는 `https://nomorevibe.com/admin/status`에서 HTTP200, Cloudflare edge 응답과 관리자 내용을 확인했다. 두 웹의 실행 설정에 개발용 `ADMIN_LOCAL_LOGIN=1`이 있었다. 코드의 proxy와 `currentAdmin()`이 이를 신원 확인 없이 허용한다. 관리자 쓰기는 시험하지 않았다.
- 이전 사용자의 관리자 접근 제한 요청에 따라 **양 웹에서 `ADMIN_LOCAL_LOGIN=0`을 적용하고 기존 웹 이미지로 먼저 재배포했다.** mini 2개·M3 4개 웹 복제본의 health를 확인했고, 공개 `/admin/status`와 `/admin/review`는307 `/admin/login`으로 바뀌었다. 일반 서비스 health는200이다.
- 관리자 OAuth client ID/secret은 미설정이고 `/api/auth/github`는503이다. 허용목록·세션 서명 키 존재와 OAuth 설정 완료는 다르다. **관리자 정상 로그인은 현재 잠겨 있으며, Tailscale 전용 접근과 요청한 아이디·비밀번호 로그인은 아직 구현하지 않았다.** 일반 사용자의 GitHub 로그인과 별도 기능이다.
- 이 임시 차단을 Tailscale/아이디·비밀번호 구현 완료로 표기하지 않는다. 운영에서 다시 local 우회를 켜는 것을 복구 절차로 삼지 않는다.

## 기능별 현재 상태

“구현”은 source에 정상 업무 경로가 있다는 뜻이다. 실제 외부 연동·장기 운영·장애 주입의 성공까지 의미하지 않는다. “부분”은 기반은 있지만 관리자 화면에서 발견→판단→처리→결과 확인이 끝나지 않는 기능이다. 세 상세 메모에는 각 행의 코드 경로·행 번호와 수용 기준이 있다.

구현 의존성: ADM01과 ADM02를 먼저 마친다. ADM04는 기존 댓글·전송 큐 연결부터 만들 수 있으며 새 공개 번역 처리 링크는 ADM07, 자동 내림 원인별 필터 링크는 ADM08의 화면이 준비된 뒤 연결한다. ADM03 상태의 unknown/stale 계약은 ADM04·11·12·15의 요약에서도 재사용한다. 각 큐의 count 조건과 처리 화면의 필터를 따로 만들지 않는다.

운영 판정 coverage도 표시한다. 현재 maintenance classifier는 uptime-ping, text classifier는 기존 네 업무 범위다. 공개 product-translate는 ADM07 ledger의 준비·실패·재시도로 별도 판정하며, 모델 연결 성공이나 일부 ready 저장을 전체 다국어 완료로 표시하지 않는다. 실행 중 유효한 job은 기존 정체 제외 guard를 유지한다.

독립 **운영 검증**도 남아 있다. 기존 monitor/Kuma의 실제 경보 수신·회복과 mini 장애의 외부 deadman, 과거 실제 보관 백업과 미디어 포함 격리 복원, 실 사용자 GitHub 로그인/댓글/외부 전송 파일럿은 코드 PR의 성공으로 대체할 수 없다. 이번 관리자 감사에서 실행하지 않았고 PENDING를 완료로 바꾸지 않는다. 사용자에게 보내는 자동 알림은 수신 채널과 명시적 발송 범위가 정해진 후 연결한다.

## 혼자 운영할 때의 동선

하단 탐색 첫 탭은 **AI로 제작**으로 통합한다. 기존 AI 근거 1·2·3단계의 공개 프로젝트를 최근 등록순으로 보여주며, 상단 8시간 급상승 및 `/rising`의 관측 기준과 별개다. 분야별 개수는 각 탭의 목록 자격으로 집계한다.

1. 관리자 접근 복구 뒤 `/admin/inbox`에서 긴급 요청과 오래된 사람 일을 확인한다. 누락 연결 PR 전에는 `/admin/feedback`과 `/admin/github-integrations`도 별도로 확인한다.
2. `/admin/status`에서 조회 실패/낡은 관측을 먼저 확인하고 역할·예비·scheduler2·두웹, 실제 저장 진행과 제공자 대기를 본다. heartbeat/접수 증가만으로 처리 성공을 판단하지 않는다.
3. 8시간 자료는 마지막00/08/16 마감과 그 직전8시간의 완료/비교가능수를 확인한다. 일반 시즌 방문 랭킹과 구분한다.
4. 현재 근거로 기존 심사/감사/제품/댓글 화면에서 필요한 항목만 처리하고 작업 기록을 확인한다. 재요청으로 쿼터·소진 상한·사람의 중단을 우회하지 않는다.
5. 재시작·drain·배포·migration·백업 복구는 기존 Dokploy/CLI/runbook으로 수행한다. 관리자에는 최소한의 상태/증거/정확한 조치 링크를 연결한다.

예상 업무 시간을 검증한 사용자 관측은 없다. “10분이면 전체 운영 가능” 같은 시간 보장은 하지 않는다. 모든 큐를0으로 만드는 것을 운영 목표로 강제하지 않는다.

## 상세 근거와 검증 한계

- [콘텐츠 감사](2026-10-13-single-operator-audit-content.md): 실제 메뉴/제품·심사·발행·근거·번역·랭킹·내림/복구·소유 확인, C1~C9 수용 기준.
- [운영 감사](2026-10-13-single-operator-audit-operations.md): 역할·정체·알림·API/AI·설정·비용·배포/백업·운영 경계, O0~O8 수용 기준.
- [사용자·접근·댓글 감사](2026-10-13-single-operator-audit-accounts.md): 인증·계정·댓글/전송·감사·요청·분석·정책, PR별 수용 기준.

상세 메모는 감사 시점의 기록이다. root의 후속 관리자 우회 차단/다국어 배포는 메모의 “진행중/미배포” 상태보다 최신이며 위 본문과 별도 배포 기록을 따른다. 코드 근거의 오류나 누락은 실제 source를 우선한다. root는 상태칩/조회 실패, held-only 검수, claimed 신고 거절, inbox 누락, repo-gone 정책의 주요 주장과 운영 접근 문제를 직접 대조했다. 계정·운영 담당의 통합 보고서 재리뷰도 완료했고 검색 캐시 지표 과장 문구를 고치고 PR 의존성·실행 중 job guard·판정 coverage를 반영했다.

개별 메뉴의 모든 브라우저 기능, 악성 댓글/외부 요청의 실제 실패 주입, 24시간 추세, Tailscale ACL/ID비밀번호 인증, 실제 백업 복원, 검색엔진 색인, 번역 문장의 의미 품질은 이 검토에서 시험하지 않았다. 기능·테스트 완료와 구현 제안을 혼동하지 않는다.
