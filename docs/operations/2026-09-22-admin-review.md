## 범위와 상태

사용자 요청에 따라 관리자 액션·인증/API, 도메인 집계·정책, 랭킹 화면을 서브에이전트 3개로 병렬 검토했다. 주 에이전트는 `/admin/status` 헤더 필터, 결과 통합, 실제 브라우저 검증을 담당했다. 기준 커밋은 `d6ed3c7`이며 이 작업의 커밋·푸시·배포는 아직 하지 않았다. 운영 서비스에 대한 조회는 읽기 전용으로 수행하고, 변경 동작 검증은 전용 로컬 테스트 DB를 사용한다.

## 화면 변경

- 랭킹: 현재 시즌 숫자 요약, 다음 시즌 예약 정책과 현재값 비교, 번호로 구분한 설정 그룹, 단위·유효범위 표시, 정렬된 숫자 표, 정책 이력. 저장 전 편집값이 미리보기에 반영되지 않는다는 점을 명시했다. CSS Module로 다른 관리자 화면과 스타일을 분리했다.
- 운영센터: 후보 이름·저장소·주소 검색, 갈래(보류 이유), AI 판단, 최소 별 수, 최근 푸시 필터를 표 헤더에 배치했다. 조건을 전체 대기 목록에 적용한 뒤 14건씩 페이지를 나눈다. URL에 조건을 저장하고 페이지 이동 시 유지하며 조건 변경은 첫 페이지에서 시작한다. 별 수 미상은 최소 별 수 조건에 포함하지 않고, 푸시 시각 미상은 기존 심사 큐 정책대로 포함한다.
- 갈래·AI 판단은 최대 2만 후보를 집계하는 기존 상한을 유지하고 한도 도달 시 화면에 알린다. 갈래 재계산은 해당 필터를 선택한 경우에만 실행한다. 필터 결과가 줄어 페이지가 범위를 벗어나면 마지막 유효 페이지로 이동한다.
- 별 수 줄바꿈을 방지하고 천 단위 구분을 추가했다. 근거 출처 지표의 모호한 “지금 처리 대상”을 “수집 기한 지난 출처”로 바꿨다.

## 남은 운영 위험과 검토 한계

- **운영 관리자 화면의 익명 접근은 해결되지 않았다.** 새 브라우저 세션에서 `/admin/status`가 로그인 없이 열리는 것을 다시 확인했다. 기존 handoff에 웹의 `ADMIN_LOCAL_LOGIN=1`, OAuth 미구성, 접근 정책 질문 미응답이 기록돼 있다. 현재 설정을 끄면 운영자도 로그인할 수 없으므로 접근 정책과 실제 로그인 수단을 먼저 마련해야 한다. 이 작업에서 운영 인증 설정을 바꾸지 않았다.
- 모든 입력·동시 사용자 조합의 무결성을 보증하는 검토는 아니다. 관리자 핵심 mutation 경합은 실제 PostgreSQL에서 재현·회귀 검증했다. 공개 `requestTakedown`의 새 요청과 관리자 처리 사이 경합은 별도 검토 가능성으로 남는다.
- 파이프라인 공개 유입은 최근 생성된 공개 제품을 세는 지표이며 과거 제품의 모든 재공개·검증 상태 전이까지 세는 지표는 아니다.
- 큰 대기열의 갈래 필터에는 문서와 근거 재판정 비용이 있다. 측정한 결과만 아래 기록하며 모든 규모의 처리 시간을 보장하지 않는다.
