# 공개 프로젝트 전체 탐색과 탑바 갱신 기준

## 공개 목록의100개 제한 제거

- 공개 목록 조회와 URL의 shown값에 있던100개 상한 제거. 처음9개, 더 보기9개 단위는 유지.
- 검색·카테고리·제작 도구·저장소 조건을 같은 기준으로 전체 개수와 목록에 적용한다. 화면에 표시할 행까지만 조회하고 전체 개수는 별도로 표시한다.
- 과도한 shown값은 실제 조회 가능한 개수로 제한한다. 동일 등재 시각은 slug로 순서를 고정한다.
- 추천의 미클레임 목록에도 전체 개수와 더 보기를 연결했다. 순위 자체의 참여 조건은 유지한다. 전체 보기 링크는 모든 공개 프로젝트를 보는 최신 목록으로 연결한다.
- 검색어가 있을 때 추천 정렬의 sort=weekly를 생략하면 최신순으로 바뀌던 기존 문제도 회귀 검사로 발견하여 수정했다. 더 보기·필터 제출 모두 정렬을 유지한다.
- 기존 차단·비공개·접속 불가 제외 기준은 유지한다. 별도로 알려드린 저장 화면의 현재 후보 목록 필터링 제한도 유지하며, 후보를9개로 축소하는 회귀를 막았다.

## 탑바의 갱신 기준

사용자가 물은337 / -7.9% /1221 /5189는2026-09-13 23:34KST 운영 DB 재집계에서도 동일했다.

- 집계 범위는 매일 한국 시간00시에 하루씩 이동하는 **어제까지 끝난 최근7일**이다. 오늘 진행 중인 날짜는 제외한다. 달력상 월요일~일요일의 이번 주나 순위 시즌과는 다른 기준이다.
- 9월13일 화면의 범위는9월6일00시 이상~9월13일00시 미만. 증감은 그 직전7일과 비교한다.
- 태어난 프로젝트는 저장소 최초 생성일을 기준으로 세며, 제품 등재 시각도 당일00시보다 이전이어야 한다. 오늘 등재한 새 프로젝트는 이 항목에 즉시 들어가지 않는다.
- 새 버전을 낸 프로젝트는 기간 내 릴리스가 있는 고유 프로젝트 수, 릴리스는 GitHub/제작자 공개 업데이트 건수다. 과거 날짜 릴리스가 늦게 수집되면 당일 수치도 달라질 수 있다.
- 별도의 집계 스냅샷 완료를 기다리지 않는다. 페이지 요청 시 DB에서 재계산하되 각 웹 프로세스에서1분간 캐시한다. 제품 공개 상태 변경도 재집계에 반영된다.
- 열어둔 페이지에는 자동 폴링이 없으므로 새로고침이나 페이지 재조회 때 새 값이 표시된다.
