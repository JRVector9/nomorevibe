# 운영센터 단계별 처리 속도 — 2026-09-22

`/admin/status` 상단에 원본 수집 → 규칙 판정 → AI 1차 → AI 2차 → 발행의 최근 1분 완료량과 5분 평균을 추가했다. 대기량, 대기 항목의 경과 시간, 집계 가능한 최근 오류 기록, 별도 재시도·심사/분류 보류량을 함께 표시한다. 기존 실시간 버튼은 자동 갱신으로 바꾸고 10초 갱신/중지 기능을 유지했다. 모든 운영센터 탭에서 표시된다.

## 집계 의미

| 단계 | 완료 속도 | 대기 |
|---|---|---|
| 원본 수집 | 최근 문서를 저장한 고유 저장소 수 | 지금 가져올 수 있는 pending + fetching 선점 항목. 미래 재시도는 별도 |
| 규칙 판정 | 최근 자동 판정이 저장된 후보 수. admin/new 제외 | worker의 judgementQueuePredicate 재사용, 후보 없는 문서와 재판정 원본 포함 |
| AI 1차 | 최근 모델 심사가 성공한 고유 후보 수. rules/재사용/admin 제외 | worker의 reviewCandidatePredicate(readyOnly:true) 재사용. 활성 lease/백오프 제외, 100건 제한 없는 count |
| AI 2차 | 최근 성공한 모델별 심사표 수. 실패 표 제외 | pending 표, 실제 호출 중 포함. failed 표 별도 |
| 발행 | crawl_publication_changes의 양수 전이 수 | worker의 심사 승인·분류 준비 조건을 충족한 approved. 나머지는 조건 대기 |

저장소·규칙·2차 표는 마지막 저장 시각을 사용한다. 재수집/재시도 전체 호출 횟수나 영구 감사 이력으로 해석하면 안 된다. AI 1차도 후보 삭제 후에는 이력이 보존되지 않는다. 1분과 5분에 동일한 상한 시각을 적용하고 미래 기록을 제외한다.

## 상태 표시

- **정체 의심**: 대기 항목의 경과가 5분 이상이고 최근 5분 처리 기록이 없다.
- **대기 많음**: 경과가 5분 이상이고 대기가 해당 단계의 5분 평균으로 30분에 처리할 양보다 많다.
- AI 1차는 화면의 모델 속도와 별도로 규칙·재사용까지 포함한 자동 처리 진척으로 상태를 판단한다.
- 꺼진 단계는 **일시 중지**, 처리 기록 있음/대기 없음도 분리한다. 최근 1분 0만으로 장애로 판정하지 않는다.
- 1차와 발행은 준비된 정확한 시각이 저장되지 않는다. 후보·원본 또는 승인·심사 갱신 시각의 추정 경과임을 카드와 설명에 명시한다. 발행은 최근 1·2차 심사/분류 시각도 반영한다.
- 2차 재시도는 생성 시각만 보지 않고 공통 워커 재시도 간격으로 경과를 보정한다. 재시도가 방금 풀린 오래된 표를 즉시 정체로 표시하지 않는다.
- 조회 오류/시간 초과는 0건으로 위장하지 않고 일시 조회 불가를 표시한다. 운영센터 나머지 기능과 자동 갱신은 유지한다.

## 조회 성능

운영 DB를 읽기 전용으로 조회했다. 최초 단일 집계는 **7,183ms**, EXPLAIN에서 JIT 컴파일에 약 **7,340ms**를 사용했다. 해당 조회의 읽기 전용 트랜잭션에만 `SET LOCAL jit=off`를 적용하고, 발행 준비 조건은 materialized CTE에서 한 번 계산했다. 최종 코드 조회는 **281ms**였다. 쿼리별 3초 제한을 두고 실패 시 화면을 보호한다. 서버 전역 설정·운영 데이터·스키마는 변경하지 않았다.

각각 다른 시각의 단일 표본이다. 이는 새 대시보드 집계의 성능 측정이며 수집/AI 워커 자체의 속도 개선 수치는 아니다. [측정 데이터](evaluations/2026-09-22-throughput/query-performance.json).
