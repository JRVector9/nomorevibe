# 제품 번역 처리량과 홈 SNS 대표 카드 복원

2026-10-23 운영 변경 전 관측은 13:31:15–14:31:15 UTC 기준 성공한 현재 `ready` 행 73개, 해당 제품 31개다. 한 건은 제품의 한 필드(tagline/description)와 한 대상 언어(en/zh-Hans/zh-Hant)의 조합이다. 제품 전체 번역 완료 수와 구분한다. 이 DB 수치는 현재 상태의 최근 저장 시각을 센 것으로 불변 이력 장부가 아니다.

기존 제품 번역은 한 배치가 약 8초여도 직렬 text 작업의 검색 프로필·검수 등을 기다려 다음 실행까지 평균 약 199초가 걸렸다. `product-translate`를 같은 text 역할의 별도 실행 줄로 옮긴다. 역할 후보를 추가하지 않고 기존 단일 역할 소유자, job lease, 현재 원문 해시, 공개/내림/편집 보류 조건 및 번역 검수를 유지한다. 한 호출 최대 4필드·원문 합계 4,000 UTF-16 code units·HTTP 20초·작업 예산 25초는 그대로다. 정기 예약은 60초이며 실제 수요가 추가 요청을 만들 수 있다. 성공 처리량은 검수와 제공자 상태에 따라 달라지므로 운영 저장 결과로 확인한다.

`PRODUCT_TRANSLATION_MODEL`은 제품 다국어 필드에만 적용한다. 없으면 기존 `ABCLLM_MODEL`/GPT-OSS 기본값을 따른다. 사유 번역·한국어 한 줄 소개·검색어 번역 모델은 이 설정으로 바뀌지 않는다. 용량 제어가 활성화된 경우에도 이 모델의 정확한 route/policy/serving 계약이 없으면 호출을 보류한다. 새 assist 제어와 공통 용량 제어의 현재 운영 모드는 바꾸지 않는다.

Supa의 실제 모델은 `Inferact/Qwen3.8-27B-NVFP4`이고 gateway 이름은 `[supa] Qwen3.8-27B-NVFP4`다. 2026-10-23 실제 runtime의 context 한도는 98,304 tokens였고, 점검 순간 실행·대기 요청은 0건이었다. 이는 지속 부하나 안전한 추가 동시성의 증거가 아니다.

같은 운영 prompt와 스키마로 실제 필드 30개를 비교했다. 현재 pending 표본 22개와 이미 번역된 공개 제품의 영문 원문을 한국어 한 줄 소개로 옮기는 별도 control 8개를 분리했다. 두 모델에 각 8회 호출했으며 출력은 평가 파일에만 저장했다. pending은 product-translate의 원래 prompt·validator, 별도 control은 product-tagline-ko의 원래 prompt·validator로 평가했다. 두 작업의 수용률을 합친 값은 단일 작업의 품질 지표가 아니다. 기존 검수 통과는 GPT-OSS 24/30(실제 pending 16/22, control 8/8), Qwen 14/30(pending 12/22, control 2/8)이었다. Qwen 2개 호출은 중첩 JSON 배열로 반환되어 8필드가 `invalid_output`이었고, 한국어 control 2필드는 `too_long`으로 거절됐다. 실패를 정상화하거나 재호출하여 점수를 바꾸지 않았다. HTTP는 모두 200, finish는 모두 stop이었다. 전체 응답 시간 중앙값은 GPT-OSS 8.58초, Qwen 4.33초, 최대는 각각 17.49초와 8.16초였다. 자동 검수 수용률은 번역 정확도와 같지 않으며 사람 정답 라벨이 없는 제한된 비교다. 이 공통 prompt 대조 실험은 초기 기준이며, 사용자 요청에 따른 AI 기준 번역·모델별 prompt 조정·새 표본 평가는 별도 단계로 보존한다.

현재 prompt의 제품 번역은 GPT-OSS를 유지하고 운영 `PRODUCT_TRANSLATION_MODEL`을 설정하지 않는다. Qwen 전용 모델 선택 기능은 준비하지만 실제 전환은 하지 않는다. 공유 gateway·Supa serving 설정도 바꾸지 않는다. 평가 원본은 `/tmp/nmv-qwen-quality-20261023`, 보고서는 `/home/ubuntu/reports/nomorevibe-qwen-translation-quality-2026-10-23`에 보존한다. 배포와 처리량 증거는 별도 운영 보고서에 기록한다.

홈 SNS의 예시 카드를 없앤 뒤 승인된 대표가 없으면 실제 목록만 가로로 표시되던 문제를 고친다. 승인된 대표가 있으면 우선하며, 없으면 이미 홈에 표시하는 실제 목록의 첫 항목을 큰 카드로 그린다. 나머지는 오른쪽 목록에 둔다. DB의 승인 결정과 `talk_only` 제외를 유지하고 실제 순위를 표시한다. 실제 항목이 하나면 카드 하나, 없으면 빈 상태를 표시한다. 예시 데이터·스타 추정값·가짜 곡선을 추가하지 않는다.

운영 모델 선택을 되돌릴 때는 text 주·예비의 `PRODUCT_TRANSLATION_MODEL`을 기존 모델로 맞추거나 제거한 뒤 Dokploy 절차로 mini 예비→M3 주를 함께 교체한다. 공통 `ABCLLM_MODEL`을 바꾸지 않는다. 데이터·요청·재시도·편집 보류를 초기화하지 않는다. 배포는 필수 최신 base CI 성공 뒤 운영 runbook을 따른다.


## 모델별 프롬프트와 AI 기준 번역을 사용한 추가 평가

사용자 요청에 따라 동일 원문의 AI 기준 번역 38개(기존 30개와 새 제품 표본 8개)를 모델 재호출 전에 고정했다. 기존 출력 일부를 본 개발 표본과 새 표본을 구분하고, 사람 정답이나 독립적인 인적 평가로 표현하지 않는다. 문구 일치가 아니라 사실·의미·조건·부정·이름·숫자·URL을 작업별 조건에 맞게 비교한다. 한국어 한 줄 요약과 다국어 본문 번역의 보존·길이 조건은 서로 다르다. 원본 참조와 별도 errata·독립 판정을 모두 보존한다.

모델별 v2.1 prompt의 같은 24입력(개발 16개·새 표본 8개) 비교에서는 GPT-OSS 자동 검수 16/24, Qwen 19/24, 두 모델 모두 7/7 JSON 배열 구조 통과였다. 새 8개만 보면 GPT-OSS 6/8, Qwen 7/8이었다. 이는 원래 30개 비교와 분모·배치 구성이 달라 직접 개선율로 합치지 않는다. 자동 검수 통과에도 성적표 기능 추가, cricket를 bowling으로 오역, 원문 중간 잘림을 임의 완성하는 등의 의미 오류가 남았다. 제한된 AI 기준 비교를 일반 번역 정확도로 해석하지 않는다.

운영 GPT-OSS는 원래 prompt를 유지한다. 추가 GPT prompt의 이점을 입증하지 못해 기본값을 바꾸지 않는다. Qwen을 선택한 경우에만 제품 다국어 필드와 한국어 한 줄 소개에 모델 전용 v2.1 suffix를 적용하는 코드를 준비한다. 이 suffix에는 개별 기준 답안이나 사례를 넣지 않는다. 기존 원문·파라미터·검수기·후처리·lease·용량 제어를 유지하며, 일반 GPT-OSS와 미지 모델의 요청은 원래 wire를 보존한다. 실제 모델 선택 설정은 변경하지 않는다.

RTX 5090 32GB의 다음 번역 전용 시험 후보는 [Hy-MT2-7B BF16](https://huggingface.co/tencent/Hy-MT2-7B)과 [Index-Translate-9B BF16](https://huggingface.co/IndexTeam/Index-Translate-9B)이다. 공식 모델 카드의 언어·구조/용어 제약 근거에 따른 우선순위이며, 이 서비스의 품질이나 5090 처리량을 직접 측정한 순위는 아니다. 신규 모델 다운로드·설치·운영 serving 교체는 이 연구에 포함하지 않는다. 상세 근거는 `/home/ubuntu/reports/nomorevibe-translation-model-research-2026-10-23/report.json`에 기록한다.
