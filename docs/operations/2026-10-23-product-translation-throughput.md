# 제품 번역 처리량과 홈 SNS 대표 카드 복원

2026-10-23 운영 변경 전 관측은 13:31:15–14:31:15 UTC 기준 성공한 현재 `ready` 행 73개, 해당 제품 31개다. 한 건은 제품의 한 필드(tagline/description)와 한 대상 언어(en/zh-Hans/zh-Hant)의 조합이다. 제품 전체 번역 완료 수와 구분한다. 이 DB 수치는 현재 상태의 최근 저장 시각을 센 것으로 불변 이력 장부가 아니다.

기존 제품 번역은 한 배치가 약 8초여도 직렬 text 작업의 검색 프로필·검수 등을 기다려 다음 실행까지 평균 약 199초가 걸렸다. `product-translate`를 같은 text 역할의 별도 실행 줄로 옮긴다. 역할 후보를 추가하지 않고 기존 단일 역할 소유자, job lease, 현재 원문 해시, 공개/내림/편집 보류 조건 및 번역 검수를 유지한다. 한 호출 최대 4필드·원문 합계 4,000 UTF-16 code units·HTTP 20초·작업 예산 25초는 그대로다. 정기 예약은 60초이며 실제 수요가 추가 요청을 만들 수 있다. 성공 처리량은 검수와 제공자 상태에 따라 달라지므로 운영 저장 결과로 확인한다.

`PRODUCT_TRANSLATION_MODEL`은 제품 다국어 필드에만 적용한다. 없으면 기존 `ABCLLM_MODEL`/GPT-OSS 기본값을 따른다. 사유 번역·한국어 한 줄 소개·검색어 번역 모델은 이 설정으로 바뀌지 않는다. 용량 제어가 활성화된 경우에도 이 모델의 정확한 route/policy/serving 계약이 없으면 호출을 보류한다. 새 assist 제어와 공통 용량 제어의 현재 운영 모드는 바꾸지 않는다.

Supa의 실제 모델은 `Inferact/Qwen3.8-27B-NVFP4`이고 gateway 이름은 `[supa] Qwen3.8-27B-NVFP4`다. 2026-10-23 실제 runtime의 context 한도는 98,304 tokens였고, 점검 순간 실행·대기 요청은 0건이었다. 이는 지속 부하나 안전한 추가 동시성의 증거가 아니다.

같은 운영 prompt와 스키마로 실제 필드 30개를 비교했다. 현재 pending 표본 22개와 이미 번역된 공개 제품의 현재 한국어 원문 control 8개를 분리했다. 두 모델에 각 8회 호출했으며 출력은 평가 파일에만 저장했다. 기존 검수 통과는 GPT-OSS 24/30(실제 pending 16/22, control 8/8), Qwen 14/30(pending 12/22, control 2/8)이었다. Qwen 2개 호출은 중첩 JSON 배열로 반환되어 8필드가 `invalid_output`이었고, 한국어 control 2필드는 `too_long`으로 거절됐다. 실패를 정상화하거나 재호출하여 점수를 바꾸지 않았다. HTTP는 모두 200, finish는 모두 stop이었다. 전체 응답 시간 중앙값은 GPT-OSS 8.58초, Qwen 4.33초, 최대는 각각 17.49초와 8.16초였다. 자동 검수 수용률은 번역 정확도와 같지 않으며 사람 정답 라벨이 없는 제한된 비교다.

현재 prompt의 제품 번역은 GPT-OSS를 유지하고 운영 `PRODUCT_TRANSLATION_MODEL`을 설정하지 않는다. Qwen 전용 모델 선택 기능은 준비하지만 실제 전환은 하지 않는다. 공유 gateway·Supa serving 설정도 바꾸지 않는다. 평가 원본은 `/tmp/nmv-qwen-quality-20261023`, 보고서는 `/home/ubuntu/reports/nomorevibe-qwen-translation-quality-2026-10-23`에 보존한다. 배포와 처리량 증거는 별도 운영 보고서에 기록한다.

홈 SNS의 예시 카드를 없앤 뒤 승인된 대표가 없으면 실제 목록만 가로로 표시되던 문제를 고친다. 승인된 대표가 있으면 우선하며, 없으면 이미 홈에 표시하는 실제 목록의 첫 항목을 큰 카드로 그린다. 나머지는 오른쪽 목록에 둔다. DB의 승인 결정과 `talk_only` 제외를 유지하고 실제 순위를 표시한다. 실제 항목이 하나면 카드 하나, 없으면 빈 상태를 표시한다. 예시 데이터·스타 추정값·가짜 곡선을 추가하지 않는다.

운영 모델 선택을 되돌릴 때는 text 주·예비의 `PRODUCT_TRANSLATION_MODEL`을 기존 모델로 맞추거나 제거한 뒤 Dokploy 절차로 mini 예비→M3 주를 함께 교체한다. 공통 `ABCLLM_MODEL`을 바꾸지 않는다. 데이터·요청·재시도·편집 보류를 초기화하지 않는다. 배포는 필수 최신 base CI 성공 뒤 운영 runbook을 따른다.
