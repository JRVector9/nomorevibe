# 2차 심사 복구 — 2026-09-17

## 확인한 원인

abc-llm 운영 서버 M3/mini의 실제 소스 해시가 로컬 abcLLM 저장소와 일치함을 확인했다. `GEMMA_ADAPTIVE_ENABLED=true`, 임계값 1,500 추정 토큰이었다. 기본 `context_strategy=auto`는 긴 Gemma 입력을 다른 모델로 추출·요약하고 시스템 지시문과 원문을 축약한다. 실제 운영 로그에서 `applied=True strategy=facts_only_extraction_v1`을 확인했다.

따라서 nomorevibe가 저장한 원문 스냅샷과 모델이 실제로 보는 입력이 달라졌다. URL이 있는데 없다고 답하고, JSON 대신 `yes` 또는 상충하는 JSON 두 개를 반환한 실패가 이 경로에서 발생했다. `context_strategy=raw`로 동일 입력을 보내자 실제 서버 로그에서 `applied=False`가 됐고 초기 실패 2개 × Gemma 2종은 모두 유효 JSON을 반환했다. 다만 로그인 벽을 승인하는 판정 오류는 두 Gemma 모두 남았다.

게이트웨이 `ChatRequest`와 전달 옵션에는 `response_format`, `reasoning_effort`, 클라이언트 `chat_template_kwargs`가 없어 해당 요청 필드가 모델 서버로 전달되지 않는다. 출력 JSON 스키마를 요청했다는 사실만으로 강제 적용됐다고 볼 수 없다. 이번 수정은 공유 abc-llm 서버를 변경하지 않고 nomorevibe에서 원문 경로를 지정하며 기존 엄격한 결과 검증을 유지한다.

Google 공식 [Gemma 4 프롬프트 문서](https://ai.google.dev/gemma/docs/core/prompt-formatting-gemma4)는 전용 thought 채널/대화 템플릿과 생각 모드를 설명한다. 다만 이번 운영 원인은 일반적인 Gemma 버그로 추정하지 않고 위 서버 코드·로그·동일 입력 대조로 확인했다. vLLM 이슈는 조사했지만 현재 MLX 운영 원인으로 단정하지 않았다.

## 모델 비교와 선택

같은 입력 14개(기존 관리자 기준 12개, 현재 정책으로 직접 확인한 2개)를 각 모델에 전달했다. 원문 전달, 동시 호출 2, 60초 제한. 초기 형식 복구 실험 6회는 아래 42회와 별도다.

| 모델 | 유효 응답 | 기준 판정 일치 | 거부 대상을 승인 | 응답 중앙값 |
|---|---:|---:|---:|---:|
| Gemma 26B / raw | 14/14 | 12/14 | 2 | 10.9초 |
| Qwen 3.8 27B / raw | 14/14 | 14/14 | 0 | 26.1초 |
| GPT-OSS 120B / raw | 13/14 | 11/14 | 1 | 15.4초 |

GPT-OSS는 게이트웨이 실패 1건, 보류 1건, 로그인 벽 오승인 1건이었다. Qwen은 해당 로그인 벽과 문서 사이트/별도 데모 혼동 사례를 거부했다. 소규모 의도 표본의 기준 일치율이며 일반 정확도 100%를 뜻하지 않는다. Qwen 최대 지연은 56.2초였으므로 운영 지연 관찰이 필요하다.

운영 선택: 기존 Gemma 26B/31B를 제거하고 **Qwen 3.8 27B + GPT-OSS 120B**를 2차 독립 의견으로 사용한다. 1차 Claude Sonnet 및 observe 모드는 유지한다. 반대 의견·보류는 사람 검토로 보내며 실패를 승인표로 만들지 않는다. 기존 Gemma 의견은 이력으로 보존하고 현행 합의에서는 제외한다.

## 코드 수정

- 심사 요청에 `context_strategy: raw`: 정책과 증거의 자동 축약 방지.
- 형식 오류를 `invalid_envelope`, `missing_content`, `invalid_json`, `schema_validation`, 근거 검증 오류로 세분화. 원문 대신 고정 오류 코드와 소요 시간 기록.
- 같은 입력·모델에서 완료된 호출이 3번 실패하면 자동 재시도를 끝내고 사람 확인으로 전환. 실패 횟수·마지막 세부 오류를 마이그레이션 0034에 추가. 배포 전 과거 횟수는 소급 추정하지 않음.
- 모델 교체 시 기존 후보에도 새 모델을 등록. 제거한 모델의 대기/실패/완료 의견은 이력으로 종료. 설정 변경 중 도착한 옛 모델 응답도 반영하지 않음.
- 과거 resolved 오류는 현재 실패 경고에서 제외하고, 재시도 종료는 상세 화면에서 직접 확인 필요로 표시.
- 공유 게이트웨이 동시 호출 8→4. 108초 작업 예산, 60초 요청 제한 유지.
