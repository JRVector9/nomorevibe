## 확정한 구현 계약

- 신규 목록은 KST 오늘 00시 이전 완료된 7일의 GitHub 저장소 생성일을 사용한다. 일반 최신순은 서비스 등재일을 유지한다. 생성일 미상/잘못된 메타/현재 저장소와 다른 과거 메타는 제외한다. 스타 50 이상이며 동일 조건의 모두 보기를 제공한다.
- 관측은 KST 00·08·16시 마감의 직전 1시간에만 GitHub를 조회한다. 회차 시작에 대상·정책·정렬용 slug를 고정한다. 기존 collector 인증·50개 묶음·quota·crawler 역할 lease와 별도 stars lane을 재사용한다.
- 회차와 관측 두 표에 7일 이력을 보관한다. `products.repoLinkVersion`과 저장소 URL 변경에만 증가하는 작은 DB trigger로 A→B→A 재연결도 이전 관측과 구별한다. 기존 product generation ID만으로는 저장소 재연결을 구별할 수 없다.
- 최신 닫힌 회차 T와 T−24시간만 비교한다. 같은 제품·저장소·연결 버전·GitHub 저장소 ID, 성공 관측, 실제 23~25시간, 해당 회차 스타 50~1,999, 순증가 10 이상 조건을 적용한다. 정렬은 순증가·회차 스타 내림차순, 고정 slug 오름차순이다.
- 기존 20시간 `product-stars-refresh` writer와 일반 StarMetric을 바꾸지 않는다. 새 reader는 현재 products.stars나 새 발굴로 닫힌 회차 순위를 다시 정하지 않는다. 삭제·차단·기본 공개 범위·생존 상태의 즉시 숨김은 유지한다.
- 모두 보기는 기존 weekly 클릭 랭킹/fallback과 분리된 `/rising`에서 같은 회차 reader를 사용한다. 비교 자료 부족과 지연을 사실대로 표시하고 이전 관측값을 현재 성공값으로 복사하지 않는다.
- Resend/GitHub 자격 정보 입력·회전·기능 flag ON·제공자 설정은 이번 구현 범위에서 제외한다. 중단한 소개 검수도 재개하지 않는다.

## 검토와 전달

각 diff를 부모가 요구사항과 소스에 대조하고 읽기 전용 독립 Codex 리뷰(`gpt-6.1-sol`, `xhigh`, 테스트/실행 금지)를 추가한다. 발견 사항을 수정한 뒤 다시 읽는다. 기존 의미 변경 때문에 필수 CI가 달라지는 fixture/기대값만 최소 수정하며 새 테스트는 작성하지 않는다. 로컬 test/typecheck/build/lint/E2E는 실행하지 않고 `git diff --check`와 저장소 보호 규칙의 최신-base 원격 CI를 구별해 기록한다.

PR01은 독립 전달 가능하다. PR02의 migration과 관측을 먼저 실행 반영해 전일 동시간대 자료를 축적해야 실제 새 급상승 순위를 볼 수 있다. PR03·PR04의 코드 완료, DB 적용, 운영 배포, 실제 회차 자료 확보 및 사용자의 기능 확인은 각각 별개로 보고한다. 자료 축적 전 공개 UI를 새 순위로 전환했다고 주장하지 않는다.


## 중간 코드 리뷰 보완

- PR01 독립 소스 리뷰의 P2(현재 저장소 메타가 있어도 이전 발행 후보 연결 때문에 누락)를 반영해 현재 URL로 원본을 찾는다. P3(Drizzle 관계 조회 extras의 decoder 유실)는 조회 후 명시적 Date 변환으로 수정한다. 신규 전체 목록의 헤더 활성 표시 P3는 공통 UI 소유자인 PR04에서 처리한다.
- 현재 URL의 대소문자 무관 조회에 필요한 원본 표의 표현식 인덱스를 PR01 migration0073으로 추가한다. 관측 migration은 Root 통합 시0074로 순서를 조정한다. 실제 성능 측정은 하지 않았다.
- 관측의 저장소 URL·연결 버전만으로 GitHub의 동일 주소 삭제/재생성을 구별할 수 없어 기존 GraphQL collector의 id를 관측에 보관하고 양쪽 ID 일치를 추가한다. collector의 isPrivate=true는 blocked로 처리한다.
- 코드 버전 상수가 바뀌어도 저장된 유효한 회차 정책을 읽고 열린 회차의 기존 창을 이어 간다. 닫힌 회차의 정책을 코드 상수로 무효화하지 않는다.
- PR02·03 독립 CLI 소스 리뷰 진행 중. PR04는 PR01의 스냅샷 커밋0937a1e 기반 별도 worktree에서 작성 중이며 아직 기능 검증이나 공개 전환이 아니다.


관측 PR02의 독립 소스 리뷰에서 P2/high confidence 두 건을 확인했다. 인증·쿼터 cooldown을 관측 실패 재시도 횟수로 소모하지 않도록 보완하며, 인증 토큰 준비가 요청 timeout 전에 실행되는 기존 collector 구조 때문에 실제 요청 시작이 회차 마감 이후로 넘어갈 수 있어 선택적 absolute deadline을 토큰 준비부터 요청 dispatch까지 전달한다. 기존 호출자의 기본 동작과 운영 인증 값은 바꾸지 않는다. 관측 lane 추가로 달라진 기존 catalog 기대값만 최소 수정한다.

## 운영 반영과 사용자 확인

이 문서의 코드 완료는 운영 반영을 의미하지 않는다. 이번 단계에서 자격 정보 입력이나 스타·피드백 flag ON을 실행하지 않는다. 코드 PR의 필수 CI, main 병합, 이미지 발행 뒤 runbook에 따라 소비자 drain·migration0073/0074를 한 번 적용·검증하고 같은 SHA의 워커와 웹을 순서대로 배포해야 한다. stale 로컬 .env의 DB는 운영 적용에 사용하지 않는다.

급상승 공개 전환에는 KST00/08/16의 정상 닫힌 회차가 최소4개, 같은 시간대24시간 전 비교 쌍이 필요하다. 실제24시간 자료가 없는 동안 화면을 배포하더라도 관측 준비 상태이며 순위가 확보되었다고 보고하지 않는다. 기존 자료를 새 회차로 채우거나 현재 스타 값을 과거값으로 복사하지 않는다.

사용자의 기능 확인 항목:
- 신규: 오래전에 생성되고 최근 등재된 저장소 제외, 기간 시작 포함/끝 제외, 생성일 표시, 홈5개와 신규 모두 보기의 순서·조건 일치.
- 급상승: 홈5개와 /rising 첫5개 일치, 회차별50~1,999스타·+10·실측23~25시간, KST집계/다음예정 표시, 페이지 이동cycle유지와만료회차새로고침.
- 실패/자료부족: 첫회차·전일자료없음·지연·실패·비교없음·조건충족없음이 각각사실대로표시되고옛일평균목록으로대체되지않음.
- 관측: 창밖GitHub요청0, 마감후쓰기차단, 재시작/역할교체, A→B→A재연결과동일주소저장소재생성의관측미혼합, 비공개/차단/삭제숨김, 시간당최대1,000행의7일이력정리.

현재 실제 처리량·성공률·DB 비용·브라우저 동작은 측정하지 않았다. 위 항목은 확인 기대값이며 테스트 성공 기록이 아니다.


관측 수정 경로 재리뷰에서 추가 P2/high confidence로 느린 optional App 토큰 발급이 정상 PAT/cached App 사용까지 막는 경우를 확인했다. 선택적 마감 경로에서 실제 GraphQL dispatch 예산5초를 남기고, 준비 예산이 끝나면 뒤의 cached 정상 토큰을 계속 확인하며 공유 자격 정보 실패로 기록하지 않도록 최소 보완한다. 수정 후 소스 재리뷰 전이므로 아직 완료로 표시하지 않는다.


PR01 main9424d6e의 원격 CI38157890474도 quality/integration/check 및 웹·워커 이미지 발행이 실제 성공했다. 이번 단계에서 해당 이미지를 운영에 배포하지 않았으며 migration0073도 아직 적용하지 않았다. 원격 CI 성공은 사용자 브라우저 기능 확인이나 운영 결과의 증거가 아니다.

신규·관측·조회·화면의 에이전트 작성은 완료했다. Root는 PR01~04 변경을 순차 통합해 파일 충돌을 방지했다. 관측 SQL 번호는0074, journal은0073 조회 인덱스 다음의74번으로 맞췄다. 부모가 모든 코드와 주요 기존 계약을 읽었고 독립 소스 리뷰 지적을 반영했다.
