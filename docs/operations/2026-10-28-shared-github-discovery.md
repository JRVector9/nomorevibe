# 공통 GitHub 탐색 작업과 적재 한도

M3의 최신·전체 탐색은 각각 고정한 기간의 모든 페이지를 처리한다. 1,000건 초과·불완전 응답은 날짜를 분할하고, 더 나눌 수 없는 구간은 재시도 큐에 보존한다. 최신 첫 페이지만 보던 이전 커서는 그 고정 기간부터 다시 확인한다. 기존 전체 탐색의 기간은 바꾸지 않는다. 검색 조건 변경·Oracle 이관 시 검증 가능한 검색어별 진행 위치를 보존한다. 오래된 커서에 개별 검색어 해시가 없으면 날짜 구간을 보존하고 해당 페이지를 재확인한다.

`github_discovery_pages`는 검색 API 종류·실제 검색어(기간 포함)·정렬·페이지·페이지크기·가시성·세대로 식별한다. 장비 이름은 식별자에 넣지 않는다. 90초 DB lease를 만료 후 회수할 수 있으며, 이전 소유자의 결과 쓰기는 차단된다. 네트워크 요청 중 DB 트랜잭션은 유지하지 않는다. 성공한 페이지 응답을 재사용하므로 응답 저장 후 워커가 중단돼도 같은 페이지를 다시 요청하지 않는다. 응답 유실 뒤 재요청까지 제거한다고 보장하지 않는다. 페이지 캐시는 전체 구간의 완주를 의미하지 않는다.

공유 범위 `public-v1`은 실제 검색에 `is:public`을 포함해야 한다. private 응답은 추가로 제외한다. 캐시는 저장소명·제한된 설명·주소·검증한 기여표기만 보관하며 커밋 본문·개인 이메일은 저장하지 않는다. M3는 페이지 claim 때 7일 지난 행을 최대 20개씩 정리한다. Oracle은 삭제 권한이 필요하지 않다. 불완전 응답 캐시는 60초 뒤 새 응답으로 교체할 수 있다.

GitHub 신규 적재는 공통 DB admission 잠금을 잡고 대기열·최근 5분 적재량을 다시 읽은 뒤 실제 신규 삽입과 함께 확정한다. 외부 요청 전 예약을 유지하는 대신 DB 최종 적재를 짧게 직렬화해 버려진 예약을 만들지 않는다. M3·Oracle 적용기가 같은 함수를 사용한다. 이미 frontier·문서·후보에 있는 저장소는 새 자리를 쓰지 않는다. 새로운 커밋의 제작 근거는 별도로 멱등 저장한다. 시간당 3,000건 설정은 최근 5분 250건 환산 방식이며 엄밀한 1시간 슬라이딩 한도가 아니다. 다른 수집원에 대한 DB 전체 강제 제약은 이 변경의 범위가 아니다.

검증: 변경 범위 단위 회귀, TypeScript, ESLint. `tests/integration/shared-github-discovery.test.ts`는 두 장비 claim 경합·소유권 교체·결과 재사용·동시 적재 상한·lease 상실 롤백을 실제 전용 DB에서 검사한다. 로컬 Docker socket 권한이 없어 실제 DB 검사는 실행하지 못했다. GitHub 필수 CI에서 실행한다.

100만 건 집계 비용은 아직 실측하지 않았다. 별도 로컬 테스트 DB를 migration한 뒤 다음 명령으로 생성한 fixture만 넣고 삭제하며 5회 집계의 p50/p95와 3초 timeout을 확인한다. 운영 DB는 검사기가 거부한다.

```sh
TEST_DATABASE_URL=postgres://nomorevibe:nomorevibe@localhost:55435/nomorevibe_test npx tsx scripts/measure-discovery-admission.ts 1000000
```

운영 배포·Oracle 활성화는 이 PR에서 수행하지 않는다. 통합 릴리스 전에 실제 DB 경합 검사와 대규모 집계 지연을 확인해야 한다.
