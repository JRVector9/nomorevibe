# 관리자에서 사람 검토를 DeepSeek에 맡기기

관리자 **크롤 설정 → 2차 심사 → 사람 검토를 DeepSeek에 맡기기**(`/admin#human-review`)에서 켠다.
기본은 꺼짐이다. 켜기 직전에 M3 Ultra의 모델 목록을 확인한다. 연결이 끊겨도 끄기는 가능하다.
심사 큐 머리에는 켜짐/꺼짐과 설정 링크가 표시된다.

켜면 `human-deepseek-review` reviewer 잡이 1분 주기로 기존 사람 큐의 직접 판단·확정 대기 후보를 처리한다.
M3의 기존 키 없는 `http://m3ultra:8010/v1`에 `deepseek-v4.1-flash-1017`만 요청한다.
외부 유료 API나 다른 모델로 대체하지 않는다. 다른 서버에서 reviewer가 활성화돼도 추론 대상은 M3다.

기존 심사 정책과 전체 근거 스냅샷을 사용한다. 근거 인용이 유효한 승인·거부와 확신 0.9 이상만 적용한다.
이 임계값은 보수적인 초기 운영값이며 정확도 보장을 뜻하지 않는다.
판단 보류·잘못된 응답·통신 실패는 사람 큐에 남는다. 스팸 의심·저장소 삭제·원본 재수집 실패는
모델이 승인하더라도 보류한다. 이미 사람이 결정한 후보와 공개 제품의 내림 결정은 이 기능의 대상이 아니다.
소개 없음은 기존 소개 생성·발행 검사를 거친다. 자동 승인으로 발행 직전 근거 검사를 생략하지 않는다.

동시 추론은 1개, 틱당 최대 2회, 호출 상한은 60초다. 실패는 15분 후 재시도하며 같은 입력·토글 세대에서
최대 3회다. 모델의 보류 결론은 같은 입력에 반복 요청하지 않는다. 스위치를 껐다 다시 켜면 새 세대다.

스위치 변경은 관리자 인증·쓰기 관문·설정 행 잠금·세대 비교 후 저장하고 작업 로그에 남긴다.
일반 설정 저장이나 기본값 복원으로 스위치가 바뀌지 않는다. 끄면 진행 중인 응답도 적용하지 않는다.
아직 발행하지 않은 위임 승인은 발행을 막고 다음 정리 틱에서 사람 큐로 돌린다. 기존 거부 기록은 유지한다.

실행은 기존 후보별 활성 심사 슬롯과 잡 lease를 사용하며 DB 트랜잭션을 추론 중에 열어 두지 않는다.
결과 저장 시 스위치 세대·후보·근거·lease를 다시 확인한다. 사람이 먼저 결정하거나 원본이 바뀌었으면
응답을 폐기한다. `crawl_review_attempts.kind=delegated`, `decided_by=deepseek`, 모델 이름·근거 해시·결과를
기록하며, 사람 처리량(`admin_override`)에 더하지 않는다. 심사 상세와 작업 로그에 위임 판단으로 표시한다.

기존 varchar/jsonb 필드만 사용하여 SQL 마이그레이션은 없다. 웹과 reviewer/scheduler를 같은 릴리스로
배포한 뒤 관리자에서 켜야 한다. 개발 중 운영 DB의 스위치는 켜지 않는다.
