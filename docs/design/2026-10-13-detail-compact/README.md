# 상세 정보 압축·업데이트 3개 시안

[시안 파일](index.html)은 외부 설치나 빌드 없이 열 수 있는 단일 HTML이다. 정보 패널은 사용자 첨부 MyGo 화면의 7개 항목과 부가 정보를 유지한다. 이번 단계는 시안과 구현 가능성 검토이며 운영 상세페이지의 코드는 수정하지 않았다.

## 제안하는 구성

**정보 패널:** 데스크톱은 4열·2행으로 바꾸고 등록 항목은 두 칸을 사용한다. 제목·값·부가 설명은 모두 표시하며 라이선스 클릭과 최신 릴리스 원문 링크·응답 시간 툴팁의 위치를 유지한다. 모바일은 2열이며 유효 방문은 마지막 한 줄로 표시한다. 글을 생략하거나 ‘더보기’ 뒤로 숨겨 공간을 줄이는 방식은 아니다.

같은 1,440px 렌더링에서 시안의 기존 3열 구성은 289.625px, 제안 구성은 166.5625px로 약 42% 낮았다. 이 비교는 시안의 동일 폭·동일 데이터 기준이며 사용자 캡처의 확대율이나 운영의 모든 화면 폭에 적용되는 수치가 아니다. 390px 시안에서는 높이327.125px였고 430px 렌더링 문서의 가로 넘침은 없었다.

**업데이트:** 최신 3개만 보여준다. 날짜·제목·출처 원문 링크를 한 줄에 두고, 제목을 누르면 아래에 내용이 펼쳐진다. 한 번에 한 내용만 열어 기본 화면의 길이를 억제한다. 출처 링크는 별도 동작이다. ‘19건 모두보기’는 내부 스크롤이 있는 창을 열고 목록·출처 필터·내용 펼치기를 제공한다. 긴 목록 때문에 배경 상세페이지 자체가 계속 길어지지 않는다. 창은 닫기·Escape·바깥 클릭으로 닫는다.

상단에서 기존 구성/제안, 데스크톱/모바일, 다크/라이트를 전환할 수 있다. 댓글·README·오른쪽 영역은 새 배치의 맥락을 보여주는 시안이며 해당 제품 기능을 새로 구현한 것은 아니다. 시안의 최신 버전 등 정보는 첨부 화면의 값, 업데이트 제목·날짜·링크는 운영 DB에서 읽은 MyGo 19건이다.

## 업데이트 상세내용 제공 가능 여부

**가능하다. 현재는 수집·표시하지 않고 있다.**

- `product_updates.summary`와 `before_after`는 이미 있으며 상세 reader도 이 값을 반환한다. 메이커는 안전한 summary를 최대5,000자로 등록할 수 있고 feed/변경 관측은 본문 요약이나 변경 전후 정보를 저장한다. `UpdateTimeline.tsx`는 이 값들을 표시하지 않고 현재 기본8개를 표시한다.
- GitHub [릴리스 API](https://docs.github.com/en/rest/releases/releases#list-releases)는 같은 응답에서 `body`를 제공한다. 현재 provider의 `ReleasePayload`/정규화에는 body가 없고 `persistReleases`는 summary를 null로 저장한다. 이미 받는 응답의 body를 저장하면 본문을 얻기 위한 추가 GitHub 호출이 꼭 필요하지는 않다.
- 10월13일 운영 read-only 조회에서 MyGo 공개 업데이트19건의 summary와 before_after는 전부 비어 있었다. GitHub 공개 API에서는 [0.4.0](https://github.com/egoist/mygo/releases/tag/v0.4.0)의 실제 본문2,956자, [0.3.7](https://github.com/egoist/mygo/releases/tag/v0.3.7)986자, [0.3.6](https://github.com/egoist/mygo/releases/tag/v0.3.6)633자를 확인했다. 시안의 첫3개 내용은 이 원문을 참고해 작성한 한국어 요약 예시이며 현재 DB에 본문이 저장돼 있다는 뜻이 아니다. 운영에 자동 한국어 요약이나 새 AI 호출을 추가하겠다는 제안도 아니다.
- 기존 외부 summary 경로는 HTML을 제거하고 최대2,000자의 plain text로 저장한다. 이 경로를 재사용하면 짧은 내용·원문 링크는 새 schema 없이 제공할 수 있다. 긴 내용을 ‘전체 본문’이라고 표시하면 안 된다. 전문을 그대로 보존하려면 별도 본문 필드/제한 또는 저장·정규화 계약 변경을 먼저 정해야 한다.
- 기존 insert는 `onConflictDoNothing`이므로 provider만 바꿔도 과거19건의 빈 본문은 채워지지 않는다. 현재 연결된 공개 GitHub 릴리스에서 summary가 없는 행만 보충하고 숨김·메이커 수정·삭제 상태를 보존하는 처리가 필요하다. 단순히 수집을 다시 돌리면 해결된다고 보고하지 않는다.
- reader는 현재 최대50건만 읽으며 공개 업데이트 GET API도 아직 없다. 범용 ‘모두보기’에서는 전체 건수와 별도 페이지 조회가 필요하다. 로드된50건을 전체라고 부르지 않는다. 시안의 MyGo는 실제19건을 모두 넣었다.

## 최소 적용 범위 제안

1. `FactsStrip`의 배치·간격만 조정한다. 값, 수집 기준, 라이선스 상태/충돌/경고, 링크/툴팁은 유지한다.
2. `UpdateTimeline`의 기본 노출을3개로 줄이고 기존 출처 필터를 재사용한다. 모두보기 내부 목록과 실제 전체 건수/페이지 조회를 연결한다.
3. 기존 summary/변경 전후부터 내용 펼치기에 표시하고, GitHub body의 저장·빈 과거 본문 보충을 추가한다. 처음에는 기존2,000자 경로의 **발췌+원문 링크**가 schema 변경 없이 가능한 최소안이다. 없는 내용은 만들지 않고 ‘아직 수집된 내용이 없습니다’와 원문 링크를 표시한다.

전문 저장이나 자동 번역을 이 최소 범위에 섞지 않는다. 운영 수집 정책 변경·강제 재수집·DB 쓰기·기능 배포는 수행하지 않았다.

## 확인 결과와 실행

HTML을 headless Chromium으로 데스크톱/모바일 렌더링하여 스크린샷과 패널 높이·가로 폭을 확인했다. 새 테스트 파일이나 로컬 기능/E2E 테스트는 작성·실행하지 않았다. 실제 운영 댓글·인증·스타 쓰기도 하지 않았다. 일반 사용자 브라우저 열기 도구는 Chrome/IAB를 사용할 수 없었고, 사용자가 브라우저 열기를 건너뛰고 파일 경로를 달라고 지시했으므로 더 시도하지 않았다.

```sh
# 로컬 파일을 직접 열거나 이 폴더만 localhost로 제공한다.
python3 -m http.server 4318 --bind 127.0.0.1 --directory docs/design/2026-10-13-detail-compact
# http://127.0.0.1:4318/
```

현재 미리보기 서버는 `/private/tmp/nomorevibe-star-growth-8h-docs-20261013`에서 위 명령으로 실행 중이다. 시안은 정적 문서여서 파일을 직접 열어도 클릭 흐름이 동작한다. 실제 서비스나 GitHub에 데이터를 쓰는 버튼은 없다.
