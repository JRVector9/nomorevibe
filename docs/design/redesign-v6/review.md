# 홈 6차 HTML 시안

모바일에서 썸네일을 식별하기 어렵다는 문제와 최근 푸시 시각·푸시 횟수 제안을 반영했다. 추가 디자인 검토 결과도 함께 제안한다. [home.html](./home.html)을 브라우저로 열면 별도 서버 없이 작동한다. 상단에서 기기 폭, 현재 이미지 크기와의 비교, 개선 근거를 확인할 수 있다.

앱 코드 대신 독립 HTML을 먼저 보여 달라는 요청에 따라 시안과 검토 문서만 변경했다. 앱 적용·머지·배포는 이후 사용자 검토 단계다. 새 사이트 구획은 추가하지 않았다.

## 제안과 근거

| 우선순위 | 기존 화면에서 확인한 문제 | 시안에 반영한 제안 |
| --- | --- | --- |
| 높음 | 390px 모바일에서 카드 폭 358px, 이미지 44/64px. Madeira 원본은 1200×400이지만 작은 사각형에 표시 | 넓은 원본은 카드 폭 16:9 공간에 contain으로 표시. 주 카드의 GitHub 아바타는 96px. 작은 파비콘은 48px로 제한하고 제품 이름과 함께 표시 |
| 높음 | 카드에서 최근 저장소 활동을 비교하기 어려움 | 썸네일 바로 아래에 최근 푸시(KST), 7일간 푸시 횟수. 집계 기준은 공통 안내 창, 확인 시각은 카드 하단. 점수·품질 색상은 붙이지 않음 |
| 높음 | 모바일 급상승 5개가 약 1,189px, 탐색 구획 시작 y≈1,409px. 첫 탐색 카드는 y≈1,901px | 급상승·새 등재는 가로 탐색. 다음 카드 일부를 남겨 탐색 가능성을 보여 줌. 390px 시안의 검토 도구를 제외한 탐색 구획 시작은 약 655px, 첫 카드는 약 950px |
| 높음 | 전체 포함 분야 21개가 모바일 7줄 | 전체·개발 도구·디자인·보안부터 보여 주고 나머지는 펼침. 선택한 분야와 초기화는 계속 보임 |
| 중간 | 인기 목록의 일부 이름에 40~88px만 남아 잘림 | 스타와 증가량을 이름 아래로 이동, 이름 줄바꿈, 태블릿은 2열 |
| 중간 | 검색 38px, 공개·분야 36px. 비활성 정렬이 Tab 탐색에서 빠지고 화살표 처리도 없음 | 조작 요소 44px 이상. 정렬은 일반 버튼으로 모두 Tab 이동 가능. 저장 상태는 이름·눌림 상태·모바일 선택 색상으로 표시 |
| 중간 | ‘많이 쓰이는’은 GitHub 스타, ‘새로 나온’은 목록 등재 기준. 홈 AI 소개에 출처 표시가 빠짐 | ‘GitHub 스타가 많은’, ‘이번 주 새로 등재된’으로 정확히 명명. AI 소개 표본에는 ‘AI가 요약 · 소개 문구’ |

밝고 차분한 화면, 기존 구획 순서, 짧은 소개, 작은 코랄 강조를 유지했다. 상세 페이지의 히어로는 이 시안에서 다루지 않는다. 색은 CSS 토큰으로만 사용하며 글자는 최소 13px, 작은 텍스트 링크의 주 색은 `--accent-ink`다.

## 실제 표본과 정보의 의미

- 탐색 목록은 운영 DB에서 읽은 공개 제품 11개다. 첫 화면에 9개, 더 보기로 11개가 표시된다. 원본 소개 문구를 유지하고 새 AI 소개는 생성하지 않았다.
- 2026-10-04 23:19 KST 전후 GitHub에서 저장소와 Repository Activities를 읽었다. 제품별 확인 시각을 보존했다. 10개는 푸시 집계 완료, workbuddy2api는 미확인이다. headcount와 LINKEDIN AGENT의 0회는 집계 완료 결과다.
- 푸시 횟수는 최근 7일(168시간) `push` + `force_push` 이벤트 수다. 커밋·릴리스·실제 사용자 수와 다르다. [GitHub 공식 API](https://docs.github.com/en/rest/repos/repos#list-repository-activities)의 페이지를 끝까지 조회했다.
- 최근 푸시는 GitHub 저장소의 `pushed_at`, 스타는 운영 DB에 저장된 확인 값이다. 카드 하단의 확인 시각은 푸시를 뜻한다. 스타까지 같은 시각에 새로 수집한 것으로 표시하지 않는다.
- 급상승·인기·새 등재·새 버전·뉴스는 같은 날 공개 홈에서 수집한 표본이다. 처음 공개된 날짜나 실제 사용량으로 이름을 바꾸지 않는다. 공개 홈의 총계와 목록 총계가 달라 운영 전체 숫자는 시안에 싣지 않았다.
- 공개 썸네일 33개를 원본 그대로 HTML에 임베딩했다. HTML을 열 때 외부 요청은 없다. 제품·등록·뉴스 링크를 선택하면 실제 공개 페이지가 새 창에서 열린다.
- 검색·분야·정렬은 11개 표본 안에서 작동한다. 기본 ‘둘러보기’는 선정 표본 순서이며 운영 추천 순위라고 주장하지 않는다. 저장은 `nmv-home-v6-saved` 시안 전용 브라우저 저장소다.
- ‘현재 크기 비교’는 기존 44/64px 크기와 모바일 세로 배치를 비교한다. 나머지 내용은 시안과 같으므로 현재 서비스의 완전한 복제 화면은 아니다.

## 독립 검토

impeccable critique 절차에 따라 A는 휴리스틱·사용 흐름을 먼저 검토하고, B는 A의 결과를 읽지 않고 detector·브라우저 근거를 수집했다. A의 평가가 끝난 뒤 결과를 합쳤다. 두 에이전트 모델은 모두 `gpt-6.1-sol`, reasoning `xhigh`다.

A의 기존 화면 휴리스틱 평가는 24/40이다. 사람이 매긴 진단 점수이며 테스트 통과율이 아니다.

| 휴리스틱 | 기존 화면 점수 / 4 | 주요 판단 |
| --- | --- | --- |
| 상태 가시성 | 3 | 저장·스타 표시는 있으나 카드의 최근 저장소 활동은 부족 |
| 현실 언어와 일치 | 2 | 사용량·첫 출시처럼 읽히는 제목이 실제 집계와 다름 |
| 사용자 제어 | 3 | 검색·필터·기준 닫기는 있지만 모바일 긴 목록이 탐색을 지연 |
| 일관성과 표준 | 2 | 일반 링크에 불완전한 탭 역할, 조작 높이 혼재 |
| 오류 예방 | 2 | 스타·새 버전·푸시의 의미를 혼동할 가능성 |
| 기억보다 인식 | 2 | 작은 이미지·잘리는 인기 이름이 식별을 방해 |
| 효율성 | 3 | 검색 단축키는 좋지만 분야와 보조 목록이 길음 |
| 간결한 구성 | 2 | 모바일 5개 카드 두 번과 21개 필터의 반복 부담 |
| 오류 회복 | 2 | 빈 상태는 코드로 확인, 실제 장애 주입은 미검증 |
| 도움말 | 3 | 집계 기준 설명과 Escape 닫기를 확인 |

인지 부하는 21개 분야 동시 노출, 두 보조 목록의 세로 반복, 스타 구간 이름 잘림, 비슷한 탐색 아이콘, 지표 의미 혼동에서 높아졌다. 첫 방문자는 기준 문구를 먼저 이해해야 하고, 한 손 모바일 사용자는 긴 보조 목록을 지나야 하며, 키보드 사용자는 비활성 정렬에 도달하기 어렵다. 시안은 펼침·가로 탐색·이름 공간·정확한 문구·일반 버튼으로 이를 줄인다.

B의 기존 markup 대상 14개와 완성 HTML 대상 1개 deterministic detector는 모두 탐지 0건이었다. 클래스 중심 JSX 스캔만으로 렌더링 품질을 증명할 수 없어서 실제 브라우저 측정을 함께 사용했다. 기존 화면에서 13px 미만 글자나 페이지 가로 넘침은 확인되지 않았으며 문제라고 주장하지 않았다.

native 브라우저 연결은 제공되지 않아 별도 headless Chromium context로 검토했다. 기존 사용자 브라우저·3017 서버·운영 설정은 건드리지 않았다. 실제 스크린 리더·200% 브라우저 확대·장애 주입·iOS 네이티브 스크롤은 아직 검증하지 않았다.

HTML 파일 자체에 `npx eslint docs/design/redesign-v6/home.html`도 실행했으나 ESLint의 HTML 설정이 없어 ignored 경고 1개였다. 이를 통과 검증으로 세지 않고, 변경된 인라인 JS를 가상 `.js` 경로로 입력해 실제 ESLint 검사를 했다. 앱 E2E는 이번 단계에서 재실행하지 않았다. 앱 소스 변경이 없는 독립 시안을 직접 검증했다.

실패를 먼저 확인한 검사는 유지했다. 320px에서 검토 도구·헤더 줄바꿈 때문에 탐색 구획 시작 기준을 초과해 헤더를 조정했고, 모바일 저장 버튼의 선택 색상이 없어서 상태 스타일을 보완했다. 24px 파비콘도 너무 작아 48px 표시 검사의 실패를 확인한 뒤 확대 폭을 제한해 보완했다. 단언을 느슨하게 바꾸지 않았다. 이미지 수집은 urllib 실패 후 curl로 바꿔 33개를 모두 받았다.

## 실제 앱 적용 전 남은 결정

썸네일 크기와 모바일 정보량을 HTML에서 먼저 검토한다. 푸시 횟수를 앱에 적용하려면 수집·저장·재확인 주기를 후속 PR 범위로 정해야 한다. 관리자 `agentEvidence.displayObservedFacts`는 켜지 않았고, 중단된 소개 검수도 재개하지 않았다.
