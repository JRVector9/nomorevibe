# 전체 흐름 4차 화면 — 할 일 표·칸 자세히 5섹션·장애 대응 표 (2026-11-04)

## 범위

`/admin/flow` 한 화면만 반영한다. 2·3차의 메뉴 27→21, 글 검수·장비 탭 합치기, 오늘 할 일 화면
리다이렉트는 이번 범위가 아니다. 주소와 기존 화면은 그대로 두고, 전체 흐름 화면과 그 화면이 읽는
자료·표시 로직만 더한다.

- 새 화면: `/admin/flow` — 발행 전 과정(탐색 → 검수 → 프로필 준비 → 발행 → 키워드 등록)의 흐름·처리량·병목,
  그 자리의 장애 대응, 1인 관리자 할 일·최근 바뀐 설정·장비·배포/점검 창.
- 쓰기 동작은 하나다: 작업 멈춤·재개. 운영센터와 같은 서버 동작(`controlJobAction`)과 폼(`JobControl`)을 쓴다.
  나머지 조치는 각 일을 하는 기존 화면으로 보낸다. 새 운영 쓰기 경로는 만들지 않았다.
- 메뉴에는 「전체 흐름」 한 줄만 더한다. 기존 메뉴 묶음·이름은 바꾸지 않는다.

## 4차에서 바꾼 것

| 자리 | 바뀐 것 |
|---|---|
| 할 일 | 경보와 사람 판단을 **표 하나**로: 구분 · 심각도 · 항목 · 건수 · 가장 오래됨/변화 · 바로 가기. 심각도 순, 숫자 열 오른쪽 정렬·`tabular-nums` |
| 모두 보기 | 칸마다 따로 그리던 목록을 **표 하나**로: 제품·항목 · 사유 · 기다린 시간. 칸은 `tbody` 하나 |
| 칸 자세히 | 모든 칸이 같은 다섯 섹션: ① 상태 ② 지금 쓰는 모델 ③ 처리량 ④ 이 칸에서 빠진 보류 ⑤ 바로 가기. 사람 심사는 보류가 모이는 쪽이라 ④만 생략 |
| 경고 | 같은 경고를 빨간 상태 상자와 모델 상자에 두 번 쓰지 않는다 — 상태 섹션 한 번, 모델 섹션은 상태 이름표만 |
| 처리량 | 숫자 칸을 같은 폭 격자로, 라벨이 두 줄이 돼도 숫자 기준선을 맞춘다. 보류는 표로 |
| 장애 대응 | 「먼저 볼 것」 번호 열 고정 + 「할 수 있는 조치」 표(종류 · 조치 · 되돌리기). 종류는 보기 · 작업 · 조심 · 화면 밖 넷 |
| 모델 표시 | 순위에 없는 장부 호출의 「어디서」를 `abcllm`(장부 provider 내부 키) 대신 연결 표지 → 장비 그룹(gpu3090) → 유일한 연결 → 사람 말(직접 연결·Claude CLI)로 표시 |
| 문장 | 2차 「먼저 볼 것」 3번이 「이 칸의 선」에서 끊기던 것을 「이 칸 「처리량」의 숫자와 그래프가 그 수입니다」로 끝맺음 |

`abcllm` 은 화면에서만 없앴다. DB·계약의 내부 키는 운영 데이터의 이름이라 바꾸지 않았다.
바꾸려면 마이그레이션과 전체 배포가 필요한 별도 작업이다.

## 읽기와 실패 처리

- 공통 읽기는 웹 여러 대가 15초 나눠 쓴다(`sharedLoader` `admin:desk:v1`).
- 칸마다 따로 실패한다. 못 읽은 칸은 0이 아니라 「읽지 못했습니다 — 0건이 아닙니다」로 쓴다.
- 모델 표시는 「작업 ↔ AI 모델」의 설정 순위와 최근 1시간 모델 장부(`model_capacity_requests`, `state=settled`)를
  비교한다. 키는 열지 않는다.
- 프로필 준비의 시간별 선은 `crawl_taglines`(오류 없이 글이 있는 행)를 더한다 — 읽기만 한다.

## 4차 카드에서 처리 LLM 바꾸기 — A안 (2026-11-04)

카드형 4차 화면을 유지하면서, LLM 줄과 자세히 「지금 쓰는 모델」 제목 옆의 「바꾸기」로 오른쪽 서랍을 연다.
5차 시안의 표·서랍 구현 중 **서랍과 순위 편집 로직만** 가져오고, 카드 레이아웃은 바꾸지 않았다.

- **여는 곳**: LLM 을 부르는 칸(AI 1차·AI 2차·프로필 준비·발행·키워드 등록·사람 심사)만.
  탐색·원본 수집·규칙 심사·공개에는 두지 않는다. 순위 읽기(`readFlowRankEditor`)가 실패하면 「바꾸기」 없이
  「작업 ↔ AI 모델」 링크만 남긴다.
- **카드 단추 중첩 없음**: 카드는 `div` + 투명한 전체 단추(`cv-card-hit`) + 형제 「바꾸기」 단추(`cv-card-change`)다.
  카드 본문을 단추 안에 넣지 않아 HTML·키보드·화면 낭독기 문제를 피한다.
- **작업별 줄**: 카드 하나에 작업이 여럿인 경우(2차 투표자 1·2·3, 프로필 준비 6개, 키워드 3개, 사람 심사 4개)를
  서랍에서 작업·투표자별로 보여준다. 카드의 모델 하나를 고르는 방식이 아니다.
- **저장**: 새 쓰기 경로 없음. 「작업 ↔ AI 모델」의 `saveAiTaskRanksAction`을 같은 폼 칸
  (`task`·`slot`·`revision`·`rank<N>Connection`·`rank<N>Model`)으로 부른다. CSRF·관리자 인증·줄 판·감사
  `ai-task-models-save` 그대로. 저장 뒤 `/admin/flow`를 revalidate 해 카드 모델과 「최근 바뀐 설정」이 갱신된다.
- **경고**: 1차·2차 같은 모델(■), 1순위 비움(■ 작업 멈춤), 2차 투표자에서 모델 뺌(▲ 재심사)을 확인 단계에서 보이고,
  위험한 변경은 확인 칸을 눌러야 저장된다. 소개 검수는 Claude CLI 계약 때문에 변경 잠금.
- **로컬 직접 연결**: `gpu3090-qwen`·`supa-direct`·`m3-mlx`는 `hasKey=false`여도 정상이다. 서랍의 연결 상태도
  `isLocalModelHost`로 판정해 「키 없음」으로 잘못 보이지 않게 했다.
- **확인**: `tests/flow-rank-editor.test.tsx` 16건, 관련 단위 7파일 128건, 통합 `conveyor-llm-read` 2건,
  `tsc`·eslint·`next build` 통과. 실제 Next 서버를 운영 데이터로 띄운 저장 확인은 하지 않았다(운영 DB 쓰기 금지).
