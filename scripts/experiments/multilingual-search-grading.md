# 4개 언어 검색 실험 추가 채점 기준

`pool` 명령은 모든 실험안·모든 언어의 상위 10개를 모은 뒤, 기존 채점(`scripts/search-judgments.json`)에 없는 질의·제품 쌍만 남깁니다. 각 쌍에는 불투명 ID를 붙이고 ID 순으로 섞습니다. 그래서 채점자는 어느 실험안, 어느 언어판에서 나온 제품인지 알 수 없습니다.

채점 대상 질의는 언어판이 아니라 그 묶음의 원래 정답 질의(key, 영어 또는 한국어)입니다. 네 언어판이 같은 채점을 나눠 쓰기 때문입니다.

채점자에게 보이는 것은 질의 원문과 제품 정보입니다(이름, 소개, 설명 앞 800자, 토픽, README 앞 1,000자). 같은 제품도 질의마다 따로 판단합니다. 제품 글이 어느 언어로 쓰였는지는 등급에 반영하지 않습니다.

| 등급 | 기준 |
| --- | --- |
| 2 | 질의가 찾는 기능, 자료 또는 작업을 제품 글에서 직접 확인할 수 있다. 명시한 주요 조건을 충족한다. |
| 1 | 주된 목적에 도움이 되는 합리적인 후보이다. 주요 기능의 일부를 제공하거나, 밀접한 대안이거나, 세부 조건 일부를 확인하기 어렵다. |
| 0 | 찾는 작업에 직접 쓸 수 있다는 근거가 없다. 같은 낱말이나 넓은 분야가 겹쳐도 목적이 다르면 0점이다. |

모호한 질의는 일반 사용자가 원문을 읽었을 때 자연스럽게 떠올릴 목적을 기준으로 판단합니다. 제품 이름만 일치하거나 기능을 추측해야 하면 등급을 올리지 않습니다. 링크를 열거나 외부 정보를 보태지 않습니다. 기존 채점, 검색 방식, 순위, ID 대응표는 보지 않습니다.

이 기준은 README 임베딩 실험(PR #992)의 추가 채점 기준과 같습니다. 두 실험의 점수를 나란히 놓고 비교할 수 있습니다.

결과는 `{"judgments": [{"id": "...", "grade": 0|1|2, "reason": "..."}]}` 형식으로 저장합니다. `score` 명령은 ID 대응표로 이것을 `multilingual-search-judgments-extra.json`(질의 → 제품 → 등급)으로 합칩니다. 기존 채점과 겹치는 쌍이 있으면 실패합니다.
