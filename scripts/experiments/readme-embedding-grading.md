# README 임베딩 실험 추가 채점 기준

pool 명령은 번역 캐시 사용·미사용의 모든 안에서 각 단계의 상위 10개 결과를 모읍니다. 기존 채점에 없는 질의·제품 쌍만 남기고 중복을 제거합니다. 질의와 제품에 붙인 불투명 ID로 순서를 섞습니다. 채점자에게는 질의 원문과 제품 이름, 소개, 설명, README 앞 1,000자가 보입니다. 같은 제품도 질의마다 따로 판단합니다.

| 등급 | 기준 |
| --- | --- |
| 2 | 질의가 찾는 기능, 자료 또는 작업을 제품 글에서 직접 확인할 수 있다. 명시한 주요 조건을 충족한다. |
| 1 | 주된 목적에 도움이 되는 합리적인 후보이다. 주요 기능의 일부를 제공하거나, 밀접한 대안이거나, 세부 조건 일부를 확인하기 어렵다. |
| 0 | 찾는 작업에 직접 쓸 수 있다는 근거가 없다. 같은 낱말이나 넓은 분야가 겹쳐도 목적이 다르면 0점이다. |

모호한 질의는 일반 사용자가 원문을 읽었을 때의 자연스러운 목적을 기준으로 판단합니다. 제품 이름만 일치하거나 기능을 추측해야 하면 등급을 올리지 않습니다. 제품 글에 나오는 링크를 열거나 외부 정보를 보태지 않습니다. 검색 방식, 순위, 기존 채점과 ID 대응표는 추가 채점이 끝날 때까지 열지 않습니다.

원본은 JSON으로 저장합니다. 질의·제품 쌍마다 ID와 0·1·2 등급이 필요합니다. 경계 사례의 설명을 `reason`으로 남길 수 있습니다. 여러 채점 파일을 사용하면 각 ID가 한 파일에만 들어가야 합니다. 채점이 끝나면 score 명령에 원본 파일과 ID 대응표를 전달합니다.

```json
{
  "judgments": [
    { "id": "00000000000000000001", "grade": 1, "reason": "주된 작업은 가능하지만 질의가 명시한 조건 하나를 확인할 수 없음" }
  ]
}
```
